## 一、三款竞品在做什么

### 1. 忘机减字谱（公众号「忘机打谱软件」）
两条产品线，都围绕「**打谱 / 录入**」：

- **两款减字谱输入法**
  - 开源版：基于 Rime 输入法框架，配自写规则词库，拼音/双拼/首字母输入，可预览组合字形。
    （2026-01-28 已由官方发文证实，细节见下方 1a：免费、Win/macOS、须装楷体）
  - 编辑器内置版：在「忘机减字谱」编辑器里重写的输入法，会**校验减字组合合理性**（比如数字在不同位置是徽位还是弦号，自动过滤不合理组合）、**优化候选排序**（全拼/简拼/混合，优先匹配当前输入）、并直接写进曲谱。
  - 核心差异点：内置版强调「**组合对不对**」「**候选好不好找**」，而不只是「能不能打出减字」。
- **云端曲谱库（1 万首容量）**：私有/公开自选、分类管理、历史版本、手机版计划中。
- 定位：**打谱录入工具 + 曲谱管理**。强在「把减字打出来、管起来」。

#### 1a. 2026-01-28：输入法正式发布（免费、系统级）

文章《忘机减字谱输入法发布：完全免费，一键上手，0门槛解锁减字谱录入》。坐实了"开源版"的实际形态：

| 项 | 内容 |
|---|---|
| 技术底座 | 基于开源输入法框架 **Rime（中州韵）** 定制开发 |
| 平台 | **Windows + macOS**（系统级输入法，不是网页/小程序） |
| 输入方案 | 全拼 / 简拼（首字母）/ **小鹤双拼** |
| 前提 | 须配合「**忘机减字谱楷体**」字体使用，否则看不到字形 |
| 外观 | 内置多款主题 |
| 价格 | **完全免费** |
| 分发 | 公众号发关键词【输入法】获取，另设用户群答疑 |

这条情报的价值不在"他们有个输入法"（早就知道），而在三个此前没想透的点：

- **它是系统级 IME，能往任何文本框里打减字**：Word、WPS、InDesign、聊天窗口都能用，且离线可用。
  这是竞品矩阵里没有的一维——我们只有自家网页里的输入框。这一维我们**不可能补**（网页做不到系统输入法），
  所以叙事上不能跟它比"在哪都能打"，只能比"不用装"。
- **录入这一环已被他们做成零成本公共品**。任何以"帮你把减字打出来"为卖点的产品，在免费 IME 面前都收不到钱。
  → 我们的价值和定价都不能押在录入上，得押在**识别**（他们完全没有）和**整段编排**上。
- **它要求用户本地装字体**，我们 `@font-face` 自带、零安装。这是"0 门槛"叙事上的真实差异，
  而且和我们 0.40.3 修的字体 404 是同一个问题域：字体没加载 = 减字静默退化成汉字。
- 时间是 **2026-01-28**，比编辑器内测早七个多月——说明"字体 + IME"这条线他们已经跑了一年多，
  编辑器是第二条线，不是临时起意。

#### 1b. 2026-09-04 更新：从"字体"走到"编辑器"，第一轮内测

文章《古琴减字谱，终于有真正的编辑器了》（原创·忘机打谱软件）宣告「忘机减字谱」**第一轮内测**开启，
耗时一年多，自称做了一套**自研排版渲染引擎**。相比上一版认知，新增/坐实了这些能力：

| 能力 | 说明 |
|---|---|
| 内置减字谱拼音输入法 | 输拼音 → 候选联想减字 → 选中直接落谱面，"不查编码、不拼字体" |
| **减字 → 简谱自动生成** | 按弦、徽位、指法关系反推；**已支持联袂指法**：同声、应合、放合、分开 |
| **时值拖动修改** | 直接左右滑改时值，谱面立即重算（不做"选中→找时值→改"的菜单流） |
| **三种排版布局** | 自然流式 / 小节换行 / 等宽小节，同一段谱可换排法 |
| 试听 + 边听边改 | 播放时看谱面，发现问题就地改 |
| 导出 | 图片、PDF、曲谱文件 |

关键判断（写下来免得下次又误判）：

- 他们**已经补上了「减字→简谱」这条反向链路**，并且做到了联袂指法粒度——我们这条链路有，但只到单字。
- 他们**把"呈现"这张牌也拿起来了**：自研排版引擎 + 三种布局，直接对着我们护城河里「活谱呈现」那一半。
- 但**仍是内测、只放少量名额**（原话「不会急着大规模开放」）。我们这边公开可访问、零登录，这个差口子还在。
- 他们依然**没有任何"识别"能力**——字体只解决"打出来"，不解决"读进来"。

### 2. 弦外古琴（公众号「潜在工作室」）
一款微信小程序，围绕「**调音 / 练习辅助 / 琴况诊断**」：

- **调音器**：10 种弦法（正调/蕤宾/慢角/清商…）可逐弦自定义并保存；基准音 390–440Hz；绿区 ±10 音分（从 ±5 放宽，因为参考琴会漂）；自动识别拨的是哪根弦，跑太远可锁定。参数用**真琴录音验证**（踩过"合成信号循环论证"的坑）。
- **节拍器**：板/梆/铎三种音色（非电子嘀嗒）；慢练 40bpm 起，可设重拍。
- **减字谱词典**：367 词条，汉字/拼音/谱字互查，面向新手。
- **我的古琴**：琴档案云端，24 款琴式线稿图鉴，历次调音连成音准走势，做「琴况诊断」。
- 不联网、免费；iOS App 在路上（同一套测音算法）。
- 定位：**调音 + 练习辅助 + 个人琴档**。强在「调音数据化、琴况可追踪」。

### 3. 古琴和音（公众号「观山院」，门户 guanshanshuyuan.cn）
一款「**网页版 + 微信小程序**」组合，背靠一个更大的**六艺文化门户（观山院）**，强调内容+社区生态：

- **网页版（轻量）**：氛围听曲在线播放、常用七弦定弦对照表、**调音记录**（登录后同步小程序云端）。
- **微信小程序（完整）**：
  - 实时拾音调音（需麦克风）、演奏记录与时间流。
  - **减字谱拍照译谱**：拍谱翻译减字谱 —— 这是它唯一触及"识别"的能力，但**锁在微信小程序内**（需装 App、授权麦克风、登录）。
  - 曲目库与练习管理。
- **生态打法**：与「修行打卡、琴箫清音」同属"书院琴事生态"；有打卡、排行、琴练时长等社交/激励玩法；门户还含文章专栏、影像、播客、短视频、FM、藏书、社区等栏目，三款小程序联动。
- 免费、浏览器即用、手机电脑通用；调音/译谱主体在微信小程序。
- 定位：**内容+社区生态型古琴工具**。强在「生态黏性、社区打卡、门户流量」。

### 4. 如意谱斋（公众号「国琴网」，官网 ruyipuzhai.com）
一款**桌面端打谱软件**（macOS Apple 芯片 / Windows x64，免费版 + 专业版，需联网验证），围绕「**减字谱 ⇄ 简谱双向转换 + 打谱编辑**」：

- **减字谱译简谱**（基础功能）：录入减字谱字，按指法/弦位/徽位规则自动算音高，输出配套简谱；散/按/泛、各类调式、复合/多音/和声组合均展开。
- **简谱转减字谱**（专业版重磅）：录入简谱旋律，软件结合调式/音高/乐句上下文匹配弦位指法，生成**多套可挑选、可锁定的减字谱候选方案**；兼顾乐句连贯、泛音/和弦/走音/特殊组合均纳入候选；一音多法（散/按/泛）对比。
- **双谱对照编辑**：页面上方简谱、下方减字谱，谱字与声响对应；支持复制/粘贴/撤销，音符时值/连线/装饰音可调，可加多层简谱行。
- **曲谱播放**：边写边听，回放校验。
- **导出**：PDF（减字谱简谱合排 / 单独减字谱 / 单独简谱，支持打印教学）；专业版支持工程包导入导出。
- 定位：**专业打谱创作工具**。强在「**双向记谱转换 + 多指法候选 + 双谱对照编辑 + PDF 出稿**」，面向打谱人/改编创作/教师。
- 关键短板（对太音的启示）：**桌面端 App、需联网验证、非浏览器**；无"拍谱识别"；无纯前端/零门槛入口。

## 三、太音的差异化空间（该坚守的护城河）

1. **唯一做「识别」的**：忘机在「录入」、弦外在「调音」、古琴和音在「生态+小程序拾音」，**没有任何一方能在浏览器里"拍一张老谱自动读出减字"**。古琴和音虽标榜"减字谱拍照译谱"，但那是**微信小程序内的能力**——要装 App、授权麦克风、登录、且被微信生态锁死；而太音的浏览器端模板匹配识别**打开网页即用、零登录、零后端、零微信绑定**。对"手头只有纸质老谱、不会打谱、不想装 App"的琴友，这是降维入口，也是三家里唯一真正无门槛的识别。
2. **呈现 + 聆听一体**：减字谱渲染（字体+SVG 双层，做成可缩放的"活谱"）+ 由减字反推简谱 + 简谱演奏 + WAV/PNG/SVG 导出，打通「看谱 → 听音 → 导出」。竞品多偏单点工具，没有这条"从纸面到声音"的完整链路。
3. **零成本可托管 + 纯前端**：browser-only、Vercel + GitHub Pages 双免费托管，用户**打开即用、无需登录、无需等后端**。竞品要么依赖后端（忘机云端曲谱库），要么虽不联网但功能孤立（弦外）。
4. **国风科技叙事**：刚完成的视觉重做（墨底七弦纹 + 青碧科技网格 + 流动辉光 + 宣纸卡片 HUD 角标），可打"**非遗科技复活**"的牌，与竞品的朴素工具风拉开调性记忆点。

## 四、太音的短板（该补 / 该说清的）

- **谱面排版已补（0.42.0）**：自然流式 / 小节换行 / 等宽小节三布局 + 疏密 + 行宽，已上线。
  与忘机的自研排版引擎仍差"按音乐内容自适应"（我们现在是固定列宽），但三种基本形态齐了。
- **联袂指法只到单字（0.43.0 已部分补齐）**：同声、应合、放合、分开是跨两三个减字的关系，
  忘机已做。我们的 `CompoundAction` 只覆盖单字内的复合右手指法（撮、泼剌、滚拂…）。
  0.43.0 补上了四种联袂的**成组与呈现**（手动标注、连音线、同声同时发声、音程提示、删除后自动解组），
  但**导入时不会自动识别**——纸谱扫进来还要人工标一遍。真正追平忘机需要识别侧的支持。
- **改时值已补（0.42.1）**：拖动即改已上线，与忘机对齐。
- **缺专业调音器**：弦外的调音器做得很细（10 弦法、±10 音分、真琴验证、自动识别弦号）。若太音用户群与弦外重叠，应明确"太音不做专业调音"，或差异化做"减字谱配套调音引导"。
- **缺曲谱库 / 社区**：忘机的 1 万首云端曲谱库是强黏性资产；太音的社区/账号/云同步仍在搁置（需后端 + 服务器）。中长期路线应错位：太音做"识别 + 呈现"，社区做"共享活谱"。
- **缺移动 App**：两家都在做原生 App，太音目前是响应式网页。短期靠"网页即开即用"抵消，长期需评估封装小程序/App。
- **做不了系统级输入法（2026-11-06 新增，且不打算做）**：忘机那份免费 Rime 输入法能在 Word/WPS/InDesign
  里直接打减字、离线可用；网页形态的我们永远做不到这一层。**不要试着补**——补它等于去做一个桌面软件，
  和"零安装、打开网页就能用"是相反方向。正确应对是承认"在哪都能打"输给它，只守"不用装"：
  我们的价值在**把已有的谱读进来**（识别）和**整段编排**，这两件它都没有。
- **识别依赖模板库覆盖**：当前 257 条模板索引对常见减字覆盖好，但生僻谱字/版刻异体可能漏识——需持续扩充索引或预留后端 Claude 识别兜底。

## 五、产品定位建议（一句话 + 叙事）

- **定位**：太音 = **"减字谱的 AI 识别 + 智能呈现 / 聆听平台"**。不与忘机抢"打谱录入"、不与弦外抢"调音练习"、不与古琴和音抢"内容社区生态"，而是占住「**识别 → 渲染 → 播放 → 导出**」这一整段，且是唯一**纯网页、零门槛**的。
- **一句话差异化**：
  > 别人帮你**打**谱、帮你**调**音、帮你**建社区**；太音帮你把**任何一张老谱，在浏览器里变成能看、能听、能导出的活谱——不用装 App，不用登录**。
- **官网 / 文章叙事**：把"AI 减字识别（网页即用）"作为首要卖点（护城河），"国风科技视觉"作为记忆点，"纯前端零成本/零微信绑定"作为 accessibility 卖点，直接对标古琴和音"拍照译谱要装小程序"的门槛。
- **2026-11-06 修正**：忘机内测版已把"呈现"纳入射程（自研排版引擎 + 三布局 + 减字→简谱 + 试听校对 + 导出）。
  所以"我们不抢打谱录入"这句话仍然成立，但**"呈现"不再是无人竞争的空白地，而是要靠排版质量正面接住**。
  对外叙事的顺序应调整为：**识别（唯一）→ 简谱自动编排（唯一）→ 呈现质量（必须追上）→ 播放导出（领先）**。

## 八、参考「虚拟古琴」（udywang.com/guqin）：另一条赛道的打法

### 8.1 它是什么

可弹奏的网页虚拟古琴（canvas + Web Audio），主界面只有几件事：

- **弹奏**：屏幕上下指法弹弦，泛音/按音切换，中英双语
- **选曲闯关**：《仙翁操》《秋风词》《随机练习》，分初级/中级/高级，进局前可"听示范"
- **音位全览**：七弦十三徽的按点图（与我们的琴面音位图同一件事）
- **录制你的专属琴音**：录一段自己的弹奏
- **古琴地图**：线下琴人/琴馆的地理分布（我们完全没有的一层）
- **下载 APP**：iOS 上架（App Store id6815482071），网页是入口、App 是正体

### 8.2 我们比它好的地方（守住，别自废武功）

| 维度 | 虚拟古琴 | 太音 |

| 记谱 | 无减字谱、无简谱，只有"音轨式"关卡 | **减字谱活谱**（字体 GSUB + SVG 降级）+ 简谱对照 |

| 判定 | 点没点中（游戏判定） | **麦克风听真琴**：音准 50 音分、绰注放宽容差、按错位置单列 |
| 门槛 | 网页能弹，App 是正体 | **纯网页零安装**，无 App 依赖 |
| 教学深度 | 听示范 + 跟着点 | 分句慢练 0.5×→1× 阶梯 + 合练 + 日课留存 |

一句话：**它是"用屏幕弹古琴的游戏"，我们是"让真琴谱活起来的工具"**。它赢在第一眼就好玩，

"古琴音游"占住了，而且一个人做都嫌内容不够，那是内容黑洞，不是我们的仗。

1. **第一眼有玩法**。打开就能出声、能点，3 秒进入状态。我们第一眼是一块空谱面和一排按钮。
   → 可吸收：空谱态给一个"点哪听哪"的琴面试玩入口（琴面音位图已有，只差把它放上首屏）。

### 8.5 WASM 可行性验证结论（2026-11-07 模拟器实测）

**结论：微信小程序 Worker 里能加载并调用我们的 Rust/WASM 编排核心。**
`apps/miniprogram-wasm-probe/` 在开发者工具 `2.02.2609250`、基础库 `3.17.5` 上跑出
`verdict: PASS / 通过：WASM 在 Worker 里跑起来了`，控制台零错误。两个真导出函数都返回了
与 Node 校验器一致的结果：

| 调用 | 返回 |
|---|---|
| `get_jianzi_variant_groups` | 减字变体组 JSON（名指/食指/勾/挑…） |
| `split_phrases_to_json` | `{"phrases":[{"end":3,"start":0},{"end":5,"start":4}]}`（句界闭区间） |

**前提与边界**（别把 PASS 读成「小程序产品成了」）：

- `WXWebAssembly` **只在 Worker 内**可用（基础库 ≥ 2.15.0），主线程没有标准 `WebAssembly`。
- `.wasm` 必须放在 `workers/` 目录**之外**（该目录只打包 `.js`），探针放在 `/wasm/`。
- 只证了「加载 + 调用 + 返回」，**没证**真机（iOS / Android 微信）、包体积、性能，
  以及 9 个导出函数在低版本基础库上的行为。
- 仍待决策：小程序端复用同一份 WASM，还是把轻量逻辑下沉。

**两个只有真机编译才会暴露、静态校验原先挡不住的坑**（都已固化成自动检查）：

1. `app.json` 必须声明 `"workers": "workers"`，否则 Worker 代码**根本不打包**，
   报 `module 'workers/wasm-worker.js' is not defined`，主线程随后 12 秒超时 FAIL。
2. 小程序 Worker **没有标准 Web Worker 的 `self`**，全局暴露的是 `worker`；
   `worker.onMessage` 回调拿到的是 `{ message }` 而不是 `{ data }`。
   写 `self.onmessage` 会报 `Cannot set properties of undefined (setting 'onmessage')`。

**复跑**（一个入口跑齐七项，任意工作目录都行）：

```bash
node apps/miniprogram-wasm-probe/scripts/verify-all.mjs
```

`verify-all.mjs` 顺序执行并汇总退出码，坏一个就整体变红、指出是哪个：

| 校验器 | 作用 |
|---|---|
| `scripts/verify-adapter.mjs` | 适配层：Node 里打真 wasm 二进制 |
| `scripts/verify-worker-transport.cjs` | 微信 Worker 传输层：模拟 `worker` / `{message}` |
| `scripts/verify-guards.cjs` | 超时 / 错误广播的兜底变异验证 |
| `scripts/verify-pages.mjs` | 页面数据链路：真 wasm 产出 → 映射渲染 |
| `scripts/verify-page-logic.cjs` | 页面行为：桩运行时跑真 wasm（点击 / 记录 / 解码） |
| `scripts/lint-project.mjs` | 工程静态约束（含 `workers` 声明、禁用浏览器 API） |
| `scripts/precheck-real-device.mjs` | 真机前静态预检 + 产物同源（默认模式；`--strict` 留给 `/tmp` 副本） |

> 各校验器的断言条数以脚本自身输出为准，不在这张表里复述——写死过一次，后面就没人跟着改。

### 9.1 它是什么

**Windows 减字谱输入法**（IME），打出减字谱字形，解决"手抄古琴谱的烦恼"。

- **作者缘起**（文章）：2006 误把古筝当古琴 → 2009 拜师李乐园 → 学琴要抄谱但书法不行 → 做了个

  没日没夜 → **V3.3.0** → 持续迭代至今。
- **官网现状**（2025-12-18，V3.6.0）：
  - 输入方式：**按减字谱部件的拼音首字母**，从左往右、从上往下
  - 徽位等数字也走拼音首字母编码；**不用/少用数字键盘，可盲打**
  - 字库 **400 多万字**（文章口径"超 500 万"），持续增加
  - 字体：楷体 / 黑体 / 篆体（其余加 QQ 群要）；文章口径"10 款字体"
  - **V3.4+ 大写状态下输出简谱符号**
- **一句话教程**（它自己写的，值得抄）：
  > 从左往右，从上往下，按减字谱首字母读音来输入。
  > 例：大九勾三 → `djgs`；因"三/四/十"都是 s 开头，规定：三=`s`、四=`ss`、十=`sss`。
  > 例：名十挑四 → `mssstss`

### 12.6 V3.4 键位设计 vs 我们的连打语法

它用 **CapsLock 大写锁定**区分「减字模式 / 简谱模式」，简谱键位：

| 键区 | 映射 |
|---|---|
| `QWERTYU` | 高音 1–7 |
| `ASDFGHJK` | 中音 1–7、0 |
| `ZXCVBNM` | 低音 1–7 |
| 小键盘数字 + `;` `'` `/` `O` | 高音点 / 低音点 / 减时线 / 泛音圈 |
| `9` `0` `[` `]`（配合 Shift） | 8 种连音线；`\` 小节线 |
| `P` | 抬升字符位置 |
| `8` | 四分之一空格（排版对齐） |
| 前置条件 | 按 `I` 切「嵌入显示」；字体必须是「蜘蛛火谱」；系统字体 `Firespide` 不能删 |

**对照**：

| | 火蜘蛛 V3.4 | 太音连打语法 |
|---|---|---|
| 模式切换 | CapsLock（物理状态） | 音色前缀 `s/f/a`（字符串里自描述） |
| 目标 | **不用/少用数字键盘、可盲打** | 分位必须带 `f` 前缀（**要用数字**） |
| 简谱 | 单向输出符号，需手工切模式 | **双向自动转换**（±2 八度） |
| 依赖 | 必须装指定字体才能显示 | 字体 GSUB 连字 + SVG 降级，浏览器即用 |

**值得拿走的一条**：它把「不碰数字键盘、能盲打」当核心设计目标。我们规划中的
**拼音直觉模式**如果也走纯字母（分位改字母而非 `f6`），上手会更顺——这是低成本改进点。

### 12.7 通稿里最该抄的：三个「轻用」场景

通稿没什么技术信息，但它把**用户真实痛点**列得很清楚，而我们对外一直在讲
「拍图出谱 / 自动编排」这类**重场景**：

| 用户 | 痛点 | 现在已能用（2026-11-07 落地） |
|---|---|---|
| 学生 | 记老师所授指法、写练习心得，手写减字谱太麻烦 | 减字键盘 / 连打敲一行 → **导出 PNG/SVG 贴进笔记** |
| 教师 | 备课做课件、批改学生作业时标注指法问题 | 网页生成的减字图直接贴 PPT，**不用装输入法** |
| 传播者 | 写文章、发视频要准确展示减字谱 | 导出 SVG/PNG，零安装、跨 Mac/Windows |

> 📌 **本节已从「建议」变成「已实现」**：写这一节时核对代码发现，此前收藏栏只导出 JSON 整包、
> 整谱才有 PNG/SVG，**单个减字根本存不成图片**——照原文案写就是虚假宣传。
> 已于 0.47.5 在「我的减字」每张卡片加「图 / 矢」两个按钮（`lib/jianzi-image.ts`），
> 截真实渲染的字块节点（字体连字与 SVG 降级两条路径都正确入画），支持 PNG / SVG。
> ⚠️ 但那一步只证明「**已存过的字**能存图」，不等于「敲一个字就能存图」——见下一段。

> 🔧 **0.47.10 补上断掉的最后一截**：写首屏引导时顺着真实路径点了一遍，发现
> 「连打敲一个字 → 存为常用 → 图 / 矢」**原本根本走不通**：`SavedJianziBar` 只挂在
> 「预览区」，而连打模式下预览区整块不渲染；加上连打是「打满即入谱、输入框立刻清空」，
> 主 state 里也没有「正在拼的字」。也就是说**最快的录字方式反而没有存图入口**，
> 照原文案对外讲就是虚假宣传（正好撞 11.4 红线第 4 条）。
> 修法：把「我的减字」移到三种模式共用，连打时 `current` 取「刚打完的那个字」
> （`lastRapid`），点选 / 拼音仍取正在拼的字；从卡片填回时若还在连打就切回点选，
> 否则填进去看不见。首屏空谱新增「只想记一个字？不必打整首谱」一栏，三句场景 +
> 一条可照做的路径 + 直达键盘按钮；卡片刻意放在 `#score-area` **之外**，
> 免得被整谱导出一起截进 PNG。三项变异验证都亮红灯，新增测试钉住闭环。
> **现在对外文案才真的能放心讲这三个场景。**

**这条已补进对外文案**：我们一直强调「一整首谱」的能力，但**记一个字、标一处错**
才是最高频的轻用场景，而且「不用装 232MB」在这类场景里优势最明显。

## 十三、一线教师自制工具与需求侧情报（2024 论文）

> 信源：微信公众号「彭介军信息科技工作室」2024-09-06 发文《抚七弦古韵长远 传琴谱形韵自如
> ——基于图像处理技术的多字体古琴减字谱录入实践研究》，作者倪慧刚（杭州市钱塘区崇德实验学校
> 信息科技教师、彭介军名师工作室成员）。**这不是竞品产品，而是一线教师的「理想工具」自述，
> 是需求侧一手样本。** 价值在于：一个真在小学古琴社团教孩子的老师，眼里的痛点与期待。

### 13.1 它是什么 / 怎么做（技术路线，与我们对照）

- 形态：教师**自制**的教学辅助小工具，**Delphi7 + TBitmap32**，图像处理 + 图层叠加（"积件成字"）。
- 减字部件库 = **99×99 px PNG**，白底转透明，逐层叠到「用户已有的简谱图片」上；源图要求 ≥2500×3500 分辨率。
- 多字体：收录《梧冈琴谱》《梅庵琴谱》《龙吟馆琴谱》《愔愔室琴谱》**四种历史琴谱字体风格**（只为"即视美感"）。
- "自动"的边界：点一个简谱音 → 列出该音在**所有弦/徽位**的减字候选（整字图形编排），**不是**简谱→减字自动转换。
- 输出：bmp/png 保存，可打印装订成"练习小册"。
- **与我们代际差**：我们是**字体 GSUB 连字 + SVG 降级**（矢量、缩放无损、可导出 SVG），他是**位图部件叠加**（固定分辨率、放大必糊）。但他解决了一个我们没直接覆盖的场景——**把减字叠到用户现成的简谱图片上**标指法。
- **顺带纠正一处自我误判**：论文最想要的「点一个音 → 列出它在七弦十三徽上的所有落点」，太音**早已作为编辑器「简谱转减字 → 查音位」实现**（`components/jianpu-translator/single-note-mode.tsx`）：选简谱数字+八度 → 点「查音位」→ 候选卡片列出「X 个位置 · 点卡片录入 · ▶ 试听」，还带按弦筛选。所以**这不是缺口，是已经能对外讲的差异化**（详见 13.3 点 3）。

### 13.2 点名的两款真实竞品（桌面输入法，已交叉核实仍活跃）

论文把当时"主流输入法和工具"定为这两款并逐一测过：

| 工具 | 形态 | 现状（交叉核实） | 核心限制 |
|---|---|---|---|
| **包松平古琴减字输入法** | Windows 输入法（IME），楷体字形 BSPGUQIN 字体 | 2012 起，2024 仍有「宋 2.6」更新，免费发布、一人一码；开发者兼营琴谱排版 | 须装输入法+重启、绑 Word/Office，**Windows only** |
| **广陵神器** | 广陵散社区出品，Word 插件式减字输入法（文鼎中楷提取笔画） | 2023-12 仍在更（v2_2023.12.07.exe），永久免费、社区账号登录；有"造字 + 云端谱字库" | 须 Windows + MS Office/WPS（带 .NET 可编程支持），**Mac/Android/iOS 不能跑** |

### 13.3 三个需求侧信号（之前文档没写）

1. **K12 / 社团「儿歌移植」场景**：小孩想弹《娃哈哈》《小草》《小星星》，网上几乎只有传统曲目。

2. **「多字体历史琴谱」（形韵自如）是真实审美需求**：论文明确要 4 种历史字体只为美感。

### 13.4 对我们的直接动作建议

- **「查音位」已覆盖论文核心诉求**（见 13.3 点 3）：编辑器「简谱转减字」选数字+八度点查音位，
  即列出该音在七弦十三徽上的全部可选落点，可点录入/试听。对外定位稿可直接讲——
  「点一个音，网页里就列出它在七弦十三徽上能怎么弹，零安装、能听、能录入」，正是桌面工具给不了、论文想要的。
  **同步修正 11.4 红线**：这条是**已实现的真能力**，可以放心讲（别再写成"待做"）。
- **多字体 = 真·高成本缺口，现在不做，且要写清原因**（避免未来误以为「加个字体切换」就能搞定）：
  我们渲染是**双层**——① 字体 GSUB 连字（主路径，当前只有 `WangJiJianZiPuKaiTi.ttf`，OFL 授权）；
  ② `svg-paths.ts` **逐字手绘**的 SVG 降级（槽位百分比是按汪楫字体逐字调过的）。
  要支持论文想要的「梧冈/梅庵/龙吟馆/愔愔室」等历史风格，**两层都要平行重做**：
  - 字体层：每套都要一份**带各自 GSUB 连字表**的授权字体（PUA 输入码→合体字的映射是字体私有的，不能复用）；
  - SVG 层：每套都要**一整套与之视觉匹配的平行路径**（`svg-paths.<style>.ts` + 重新调槽位），
    这是已有的主要工作量来源（MEMORY 纪律：svg-paths 只能增量追加、勿跑全量 extract）。
  → 结论：**纯审美需求、零功能增益、成本等价于把渲染层重写 N 遍**。进 roadmap 但**优先级最低**，
  触发条件应是「拿到明确授权字体 + 有真实需求信号」，而非现在动手。
  **需求侧反证（2026-11-07 补）**：火蜘蛛 V3.0 首发帖里，作者自己写「现有篆体，**没啥卵用，就图个乐字**，
  纯粹吹牛叉」（见 12.10 事实 3）。**做多字体最多的那家自己都说非刚需** → 这个优先级判断不用再讨论。
- **分发优势再确认**：对方是「百度网盘 + 装输入法 + 重启 + 绑 Office」，我们是「开网页 / 小程序」，
  这条差距比任何单点功能都直观，对外可放心讲。

### 14.2 案例 A：老减字谱 → 数字化（识别方向）

- **输入**：一份公开减字谱书页（如入门必弹的《仙翁操》公开教学版）。
- **步骤**：整页识别 → 逐格校正 → 减字反推简谱（双谱对照）→ 导出。

| 步骤 | 对应能力 | 状态 |
|---|---|---|
| 整页切分 + 识别 | AI 整页识别（`sheet_segment` + 模板匹配） | ✅ 已上线 |
| 逐格校正 | 单字识别 + 逐格修正 | ✅ 已上线 |
| 减字 ↔ 简谱互看 | 减字反推简谱 + 双谱联动高亮 | ✅ 已上线 |
| 出图/出声 | 导出 PNG/SVG/PDF + WAV 试听 | ✅ 已上线 |

- **诚实边界（照 11.4 红线）**：整页识别是 **best-effort**，书页缩到 24px 行高时整字 exact 率约 59.5%，
  需 **≥3× 导出**提精度；复杂版面要人工逐格校正。我们**不称 100% 自动**，反而强调「识别 + 你点一下校正」比纯手工快得多——这正是硬核琴友群体更买账的讲法（见 12.8 #1）。

### 14.3 案例 B：简谱 → 减字谱（创作方向）

- **输入**：一段数字简谱（如《仙翁操》简谱，或儿歌/考级小曲）。
- **步骤**：简谱转减字 → Viterbi 多候选编排 → 查音位选指法 → 导出。

| 步骤 | 对应能力 | 状态 |
|---|---|---|
| 简谱 → 减字 | `translate_jianpu`（WASM，**零后端**） | ✅ 已上线 |
| 多指法编排 | Viterbi 最优指法 + 多候选 + 分句 | ✅ 已上线 |
| 点音查全部弦徽 | 编辑器「查音位」：一个音列出七弦十三徽全部落点，可录入/试听 | ✅ 已上线（已截图取证） |
| 出图/慢练 | 导出 + 分句慢练进度 | ✅ 已上线 |

- **诚实边界**：编排是**启发式最优**，用户可手动覆盖；小学/儿歌这类简单旋律天然友好，但复杂传统大曲仍需人审。

### 16.2 AI 释谱（2021-11，中央音乐学院）：识别早就有人做，但做的是另一件事

王悠荻（中国首位古琴演奏博士）+ 魏冰（音乐人工智能系博士）领衔，获第七届"互联网+"北京赛区三等奖，

官方自述五大优势：**3 万减字数据集** / 自主矢量字体（可无限放大，供出版印刷）/
录入排版快 / **AI 识别手写体与扫描版减字** / 团队懂古琴可自校验。
**商业模式**：面向印刷出版行业的**定制方案**，扫码联系客服 —— 不是自助产品。

> **关键差异（这是我们最该讲清的一句）：**
> **它识别的是「字形」，输出是印出来的谱；我们识别的是「指法」，输出是可编辑、可播放、可转简谱的数据。**
> 字形只能拿去印；指法能弹、能改、能听、能导 MIDI。
>
> 换句话说：它做的是「把纸上的谱**搬**进书里」，我们做的是「把纸上的谱**变活**」。
> 两者在同一张照片上分道扬镳，且**它这条路更成熟（2021 年至今、有出版背书）**。

另需注意：AI 释谱的母项目还承诺过「AI 智能打谱 + 古琴音乐自动生成」，并把「复活古曲三千首」当愿景。
这与我们「不做 AI 生成」的判断不冲突，但**它已经把「AI + 古琴」的话语权占了五年**。

### 16.3 古谱今译（上海音乐出版社 + 上海慧游）：出版社级在位者

腾讯「探元计划」公开报道（一级）：上海音乐出版社与上海慧游文化共建，做
**AI 解码减字语义、建立 MEI 古琴数字规范、研发零门槛输入法、探索 AI 打谱与创作**，
已建成收录 **3000 余首琴谱**的「爱」减字谱网站，目标是「让古老记谱体系重获可听性」。

意义：**出版行业自己在做这件事**，而且带着规范（MEI）和曲库（3000 首）。
这不是一个能靠"做得更好用"就绕开的对手——它手里有**内容资产和行业标准**。

### 16.4 七家摆在一起，我们的位置到底在哪

> ⚠️ **本节已于 2026-11-07 二次修订**：原表漏了「查字」这一代（爱搜减字 2015、华夏古琴网 2021），
> 导致下面「只有我们入口是你不会」的结论是**错的**。表已补两行，结论已重写，完整推演见**第十七章**。

| 产品 | 起点 | 入口是「谁先动手」 | 有识别 | 有声音 | 形态 |
|---|---|---|---|---|---|
| 火蜘蛛 | 2023→ | 你敲 | ❌ | ❌ | Windows 输入法 |
| 丝桐里 | 2023-07 | 你敲 | ❌ | ✅ | 手机 App（订阅） |
| 德音打谱坊 | 2023-09 | 你交需求 | 人工 | ❌ | 高校外包服务 |
| AI 释谱 | 2021-11 | 你交纸谱 | ✅ **字形级** | ❌ | 出版定制 |
| 古谱今译 | 2024→ | 你查库 | ✅ | ✅ | 出版社数字库 |
| **爱搜减字** | **2015** | **你手写** | ✅ **单字检索** | ❌ | 网页，免费 |
| **华夏古琴网** | **2021-07** | **你手写/拍照** | ✅ **单字检索** | ✅（老师录音） | 微信小程序，免费 |
| **丝桐**（2018，已停运） | **2018-08** | **你已经在学** | ❌ | ✅（合成+录音回放） | iOS app，免费 |
| **灵弦** | 2026-09→ | 你敲 | ❌（计划中） | ✅ | 在线编辑器 SaaS |
| **太音** | — | **你给图 / 给数字** | ✅ **整页结构化** | ✅ | 静态网页，免费 |

**结论（2026-11-07 修订版）：**

> 入口是「**你还不怎么会**」的，**不止我们一家**——2015 年的爱搜减字、2021 年的华夏古琴网都是，
> 而且免费。但它们把终点的位置定在「**这一个字是什么意思**」：候选 → 释义 → 视频 → 出处，到此为止。
>
> 入口是「**你已经会弹**」的，是火蜘蛛、丝桐里、灵弦，终点是「**一首谱**」，可编辑可导出。
>
> 还有第三类入口：「**你已经在学了**」——2018 年的丝桐（iOS，免费）走的就是这条：曲目由官方录好，
> 你只负责跟着一句一句练。它不解决「谱从哪来」，所以只能等官方一首一首录（试运行期只有 5 首），
> 这也是它停在原地的结构性原因（见第十九章）。
>
> **我们的位置不在任何一代里，而在两代之间**：接过第一代的入口（不会也能进），
> 交到第二代的出口（出去是一首谱）。
>
> 所以自我描述不该是「更好的编辑器」（灵弦领先），也不该是「能认减字」（2015 年就有），
> 而应是「**把『没有指法』的状态，变成『有指法、能听、能改』的一首谱**」——
> 别人做的是单点，我们做的是这条链。

### 16.5 该怎么办：补什么、不补什么、怎么讲

**该补（按性价比排序，前两条是纯工程量）**

| 项 | 为什么 | 成本判断 |
|---|---|---|
| 定弦 3 → **8** 种（先做能自证的） | 灵弦 11 种是硬指标，用户会直接对比。**清单见 17.5 ①，其中只有 8 条能靠算术自证** | **中**（原判「小、无架构改动」已作废）：Rust enum + 级数表 + serde + 检索校验 + 前端表 + 两侧测试，见 17.5 ①(c) |
| 版本历史（本地） | 它用「改动看得见」打痛点，很打动人；我们无账号，可用本地快照 | 中，localStorage 存差分 |
| PDF 导出 | 它免费版就给带水印 PDF，我们只能打印 | 中，可用打印样式 + 分页控制 |

**不补（这是我们和它的路不同，不是落后）**

- **多人实时协作**：要账号 + 后端 + 冲突合并，与「纯前端、无账号、可离线」的定位直接冲突。
  我们的答案应该是「**导出文件 / 减字码发给对方**」——够用且不用注册。
- **教材整册编辑**：B 端出版场景，AI 释谱与古谱今译已在位，且有行业背书。

**怎么讲（对外三句话，替换掉过时的旧口径）**

1. 别说「只有我们能做减字谱」。准确说法有两半：**「编辑器已经有好几家了，但都得你先会弹」**
   ＋ **「查字的工具 2015 年就有，但它只告诉你这个字什么意思」**（见第十七章）。
2. 我们的差异化只讲一条，讲透：**「给一张老谱照片、给一段简谱数字，它就能变成能弹、能听、能改的谱。」**
3. 被追问功能少（没有五线谱/协作），**不辩解，直接换问题**：
   「那些是编辑器要解决的问题。我们解决的是编辑器前面那一步——**谱还没成形的时候，怎么进来**。」

### 16.6 这次核出但未定论的

- 灵弦的**识别是否真在开发中**，只有路线图自述（第 4 阶段），无时间表。若它上线识别，我们的窗口会显著收窄。
- AI 释谱的**现状**：2021 年发布后，除央音通稿与媒体报道外，未核到独立产品站或价格，
  是否仍在对外服务**不确定**（可能是课题组项目而非持续运营的商业产品）。**引用时只说"2021 年发布过"，不说"现在仍在运营"。**
- 古谱今译的「爱」减字谱网站**未访问核实**（仅凭报道），曲库 3000 首为其自述数字。
- 灵弦的 37 种指法与我们的覆盖范围**未做逐项比对**，留待需要时再核。

## 十七、最早的「入口」其实在 2015 年：爱搜减字 + 华夏古琴网

> 情报时间：2026-11-07。触发来源：公众号「古琴小助手」《华夏古琴网，一个能手写查找减字谱，又能寻找身边琴友的小程序》（2021-07-13）。
>
> **这一章要做的事不是加一个对手，而是修一个错误。**
> 第十六章写「除我们之外，入口都是『你已经会弹』」——**这句从今天起不成立**。
> 2015 年就有人在网站上让你手写一个字来查它，2021 年有小程序让你拍照认它，两家都免费。
>
> 信源分级：
> - **一级（自述一手）**：华夏古琴网公众号原文（2021-07-13，公众号「古琴小助手」，转载自「华夏古琴网」）
> - **一级（我亲自访问实测，2026-11-07）**：isojz.com 首页 / `/list` / `/yinwei` 三页
> - **未核**：华夏古琴网小程序本体（微信内，无网页可访）；爱搜减字的识别是否为真图像识别

### 17.1 华夏古琴网：一个 2021 年的原生小程序，八个功能，全部永久免费

它的自我介绍先说清了为什么存在：微信群里天天有人问「这个指法怎么弹」「有没有 xx 地方的琴友」「哪家琴社好」——
于是做了「**查字 + 找人 + 看视频**」三件事合一的工具。

| 功能 | 它做的事 | 与我们的关系 |
|---|---|---|
| **减字谱识别** | 查指法释义 + 对应教学视频，收录《琴学备要》几乎所有指法 | **正面重叠**，且它多了视频 |
| 附近琴人 | 看附近琴友，可分享到群看距离 | 社区侧，我们没有 |
| 附近琴社 | 查附近琴社与斫琴师，给联系方式 | 我们自建曲谱库，形态不同 |
| 琴坛直播 | 收录古琴直播（发布时**一场都没有**），公益直播免费技术支持 | 无 |
| 琴学比拼 | 古琴知识答题 + 分享 + 现金红包 | 拉新手段，成本极低，值得记 |
| 古琴杂谈 | 聚合几乎所有古琴公众号文章 | 内容聚合，我们无 |
| **智能评分** | 对比自己弹奏与老师的差异并打分——**作者已主动关闭** | **反面教材，见 17.5** |
| **古琴播放器** | 上传老师音频、指定片段循环、片段加速减速 | 与我们的慢练重叠，见 17.5 |

**价格口径（原话）**：「所有的功能完全是免费的，而且是永久免费（即使是琴社入驻也是免费的）」——
这不是促销话术，是一个已经把「古琴工具该不该收钱」这件事定过性的表述。**用户的价格预期是 0。**

### 17.2 全文最值钱的一句：识别不准时，它让用户「往下滑」

原文关于识别只说了两句，两句都要背下来：

> 「需要说明的是，这个功能的训练数据有限，**所以准确率有待提升。您往下滑动即可找到对应的指法。**」

> 「此功能使用了广陵散社区的『广陵神器』及爱搜减字中的**减字谱图片**。」

这两句合起来，说明 2021 年那批人的完整做法：**用别人现成的减字图片建索引 → 用户拍照/手写 → 图搜图给候选 → 不准就让用户滑列表 → 点进去看释义和视频。**

也就是说：**识别被降级成了检索。** 不确定性的出口是「人往下翻」，而不是「人改一下再进谱」。

这正是我们和它们的真正分界，而且**不是准确率的分界**：

| | 它们（2015–2021） | 我们（现状） |
|---|---|---|
| 输入 | 手写一个字 / 拍一个字 | 拍一整页 / 一段简谱数字 |
| 输出不准时 | 给候选列表，**你自己往下滑** | 逐格校正，**改完变成结构化数据** |
| 终点 | 「这个字是什么意思」+ 视频 | 「这一首谱能弹、能听、能改、能导」 |
| 交付物 | 看完就关掉 | 一份可保存、可导出的文件 |

> **对外可以这么说：**「早就有拍照认减字的了，但它们认得不准的时候，是让你自己去列表里翻。
> 我们认得不准的时候，是让你改——改完它就是一份能弹的谱。**差别在不准之后发生什么。**」

### 17.3 爱搜减字（isojz.com）：2015 年就在做手写查字，且有「出处」

华夏古琴网承认数据来自它，于是顺着查了过去——**这家比小程序早六年，而且形态更接近我们。**

备案号 **粤ICP备15105043号**（2015 年），站名「搜减字」，三个栏目：

| 栏目 | 实测内容 |
|---|---|
| **查询** | **手写板**（回退 / 重写 / 查询）+ 四个 tab：**候选 / 描述 / 出处 / 讨论** |
| 探索 → 谱字 | 「共 15 条记录」 |
| 工具 → **古琴音位图生成器** | 显示模式三档、图片尺寸三档、按音图/泛音图、**16 种定弦**、散音音高可选 |

三点判断：

1. **「出处」tab 是它最特别、而我们没有的东西**：它把一个减字和「哪些谱里出现过」关联起来。
   我们反过来——有曲谱，但单字的谱例溯源没做。
2. **它的内容规模很小**：探索只有 **15 条**。所以别被华夏古琴网那句「收录的减字谱比我们的齐全」
   误导——那是「比这个小程序齐全」，不是「量大」。**不要把它当成曲库对手。**
3. **它的音位图生成器是白送的工程资产**：16 种定弦带完整调名别名，见 17.5。

### 17.4 修正后的三代划分（替换 16.4 的结论段）

原来写「查字—录谱」两代，漏了「查字」这一代。

| 代 | 代表 | 入口（谁先动手） | 终点停在哪 |
|---|---|---|---|
| **① 查字** | **爱搜减字 2015**、**华夏古琴网 2021** | **你不会** → 手写 / 拍一个字 | **一个字**：候选 + 释义 + 视频 + 出处。**不产出谱** |
| ② 录谱 | 火蜘蛛 2023、丝桐里、灵弦 2026 | 你会 → 敲 | **一首谱**：可编辑、可导出 |
| ③ 成曲 | **太音** | **你不会** → 给图 / 给数字 | **一首谱，且能听、能改、能导 MIDI** |

**修正后的定位（这句话替换掉 16.4 的结论）：**

> 入口不需要「你会弹」，这件事 2015 年就有人做到了——手写一个字，它告诉你这是什么意思。
> 但那条路走到底只到「**这个字是什么**」，到不了「**这一句怎么弹**」。
>
> 我们做的是把那个入口接到后面的出口上：**一张照片进来，出去的是一首能弹、能听、能改的谱。**
>
> 所以护城河不是「能识别单字」（2015 年就有、还免费），
> 而是**整页切分 → 结构化指法 → 出声**这三件连起来。单点都能被追上，连成一条链要重做三次。

这条修正还有一个副作用，必须写进红线：**以后不能说「没人做过减字识别」。**
古琴圈很小，这句话一出口就会被当场纠正，而且会把「整页识别」这个真优势一起赔进去。

### 17.5 五条该拿 / 该认的（按价值排序）

**① 定弦表：16 种，带调名别名——但「可直接抄、成本几乎为零」是错的（2026-11-07 复核后改写）**

爱搜减字的音位图生成器把 16 种定弦连同别名、调号、紧慢弦规则全列了。这是我们文档里第一次拿到**完整且带别名**的定弦清单（此前只知道灵弦有 11 种、我们只有 3 种）：

|---|---|---|---|
| 1 | 正调 | 仲吕调，F 调 | — |
| 2 | 蕤宾调 | 金羽调，清羽调，bB 调 | 紧五弦 |
| 3 | 慢角调 | C 调 | 慢三弦 |
| 4 | 清商调 | 姑洗调，夹钟调，bE 调 | 紧二五七弦 |
| 5 | 慢商调 | C 外调 | 慢二弦（全） |
| 6 | 无射调 | 黄钟调，复古调，侧楚调，bB 外调 | 紧五慢一（全） |
| 7 | 凄凉调 | 楚商调 | 紧二五弦 |
| 8 | 侧商调 | D 外调 | 慢三四六弦 |
| 9 | 商调 | D 调 | 慢一三四六弦 |
| 10 | 离忧调 | — | 紧五慢一二弦 |

> ⚠️ 这张表**不能直接抄进 `lib/tuning.ts`**。上一版这里写着「成本几乎为零」，是没验算就下的判断；
> 2026-11-07 把它算了一遍（`scripts/derive-tunings.mjs`，可复跑），结论是三条都要改口：

**(a) 「（全）」= 全音，不是整弦松动 —— 这条现在可以定论了。**

把「紧 = 升半音、慢 = 降半音」直接套上去，#5 慢商调 和 #6 无射调**算出来的音阶里根本装不下源站自己标的调名**
（慢商标「C 外调」，算出 C D♭ F G A C D，没有哪一宫能容纳；无射标「bB 外调」，算出 B D F G B♭ C D，同样无解）。
把这两条里带「（全）」的那根弦改成**降全音**（慢二 → D 降到 C；慢一 → C 降到 B♭），两条同时对上：

| 读法 | 慢商调 | 无射调 |
|---|---|---|
| 全按半音 | C D♭ F G A C D → **无宫可容** | B D F G B♭ C D → **无宫可容** |
| 「（全）」按全音 | **C C F G A C D → 候选宫 C/F/B♭，含标注的 C** | **B♭ D F G B♭ C D → 候选宫 E♭/F/B♭，含标注的 bB** |

两条独立的调同时只有全音读法讲得通，比单条吻合可信得多。**「全」指全音。**

**(b) 16 条里只有 8 条能靠算术自证，其余必须回《琴学备要》原文。**

判据：七弦音高是否全部落在标注宫音的**清乐七声**（五声 + 清角 + 变宫）内。用全音修正后：

| 结果 | 有哪些 |
|---|---|
| ✅ 自证通过（8） | 正调 F · 蕤宾 B♭ · 慢角 C · 清商 E♭ · 慢商 C · 无射 B♭ · 商调 D · 慢宫 G |
| ❌ 与标注矛盾（1） | 侧商调（标 D 外调，按「慢三四六」算出 C D E F♯ A B D，只可能是宫 G；试过慢三六 / 慢三四 / 慢四六 / 慢三 / 慢六 五种读法，**没有一种给出 D**）|
| ⚠️ 判据给不出唯一宫音或源站未标（7） | 凄凉 · 离忧 · 间弦 · 无媒 · 碧玉 · 玉女 + #16 侧商重复项 |

其中两条要特别当心：
- **碧玉调「紧三慢一四六」** 算出三弦与四弦**同音 F♯**。琴上两根相邻弦定成同音不是不可能，但更可能是我们对记法的理解（是「慢一、四、六」还是「慢一四六」连读）与源站不同。
- **凄凉调「紧二五」** 判据给出宫 E♭ 或 B♭ 两个解，靠算术定不了。

**(c) 跨栈成本：不是「零架构改动」。**

`Tuning` 在 Rust 里是 **enum**，`open_strings()` 返回的是**简谱级数**（`Pitch::new(5, 0)` 这种），不是 MIDI——
真正决定音高的是 Rust 那张级数表，前端改不动它。加一种定弦要同时改：

| 位置 | 改什么 |
|---|---|
| `crates/taiyin-core/src/jianpu.rs` | enum 变体 + `#[serde(rename)]` + `open_strings()` 级数表 |
| `crates/taiyin-server/src/routes.rs` | 检索 `tuning` 参数的合法值校验（非法值要 400） |
| `apps/web/src/lib/tuning.ts` | `TUNINGS` 条目 + `TuningId` + `isTuningId` |
| 前端 UI | 定弦下拉 / 调音器 / 载入对话框（后两者遍历 `TUNINGS`，自动跟上） |
| 测试 | 两侧都要；Rust 侧的级数表是唯一真相 |

> **结论：先只加那 8 条能自证的（净增 5 种），一次跨栈改到位；其余对着《琴学备要》核过再说。**
> 数量上 3 → 8 看着仍不如对手（11 / 16），但定弦表错一根弦的后果是**整首跑调而谱面看不出任何异常**，
> 这比少几种定弦严重得多。对外可以照实说：「我们只收规则能互相印证的定弦，错了比少了糟。」


**② 指法释义 + 教学视频：认差距，不补**

它收录《琴学备要》全部指法释义 + 网络教学视频，免费。我们的释义是文本生成的，没有视频。
补视频要版权 + 拍摄成本，且对方免费——**补了也不构成优势。这条直接认。**

**③ 「智能评分」作者主动关闭：我们不做自动评分的第二个独立证据**

原话：「相应的技术并不完善，而且**对录音环境有很高的要求**，所以我们关闭了此功能」。
第一个证据是我们自己实测的 LLM 直接识别 exact 0%。
**结论加固：对外一律不提「AI 评分 / 弹得好不好」这类能力，连「计划中」都不说。**

**④ 「慢练」不是我们的差异点——但暴露了一个真需求**

它的「古琴播放器」= 上传**老师的音频** + 片段循环 + 变速。2021 年、免费、就在小程序里。
所以「能慢练」这件事不构成对比优势。但它说明真需求是：**用户练的是自己老师的录音，不是合成音。**
→ 记进观察，不立项：若将来做音频导入，成本在「时间轴对齐」，不在播放。

**⑤ 价格预期是 0**

永久免费 + 琴社入驻免费。灵弦的 ¥12/月 是逆着这个预期走的。
我们免费、无账号的策略在这个赛道里是**符合预期**，不是「还没想好怎么收钱」——被问到时可以这么说。

### 17.6 这次核出但未定论的

- 华夏古琴网**小程序本体是否还活着**：文章 2021-07 发布，「琴坛直播」当时 0 场，之后无更新痕迹。**未打开验证。**
- 文章标题写「**手写**查找」，正文功能名却是「减字谱**识别**」——从 17.3 的实测看，主体是**手写板输入**。
  引用时说「手写/拍照查字」，别说成「拍照识别整页」。
- 爱搜减字的识别是**真图像识别**还是笔顺/部件匹配，未验（无登录无法调用）。
- 「收录《琴学备要》几乎所有指法」的实际条数未核。
- 华夏古琴网的开发者身份、是否仍在维护，全无信息（文章只留了「负责人微信」）。

### 17.7 已经落地：谱例溯源（2026-11-07，同日实现）

**做了什么**：释义面板（键盘预览区）在琴面图下面多了一块「谱中见过」——
把当前这个字在所有曲谱（内置示例 + 本机「我的曲谱」）里的每一处列出来：
`来源 · 曲名 · 第 N 句 · 第 M 音`，**点一下当场试听这个字**。

**这是本轮唯一真正「覆盖对手」的动作**，因为它接的正是爱搜减字那个「出处」tab：

| | 爱搜减字 / 华夏古琴网 | 我们 |
|---|---|---|
| 有「出处」 | ✅ 字 → 哪些谱 | ✅ 字 → 第几句第几音 |
| 点进去看到什么 | 谱的**图片** | **位置**（句号 + 音序） |
| 能听吗 | ❌ | ✅ 点一下就出声 |

差别不在功能名，在**数据形态**：它们的曲谱是图片，索引只能指到「哪一页」；
我们的曲谱是一列结构化音，索引能指到「第几个音」，而这个音本来就带音高。

**实现要点（后续改动别踩）**：

1. **严匹配优先，无结果才退宽匹配**。严 = 连弦号都一样；宽 = 同指法换了弦，界面标「别弦」。
   两种不混排——混着会把「这句里也有它」稀释成「这个动作还能落在别处」。
2. **左右手指法要归一**。键盘给偏旁（`勹`）、粘贴传统谱本给全字（`勾`）、`尸`/`劈` 并存，
   不归一就是「同一个字两个键、互相查不到」。借 `jianzi-explain` 的释义表统一成 `name`。
3. **句号必须问 WASM**（`splitScorePhrases`），前端不抄气口阈值；切句失败就只说第几个音，不猜。
4. **弦号与徽位同名**（一～七）：任何点选式验证脚本点「四」都要取最后一个，否则点到徽位。

**边界**：曲库只有示例谱 + 本机谱，社区曲谱未接。

> 修订（2026-11-07 实测）：原写「在谱面里点某个字查出处还没做」是错的。谱面点一个音会进编辑模式
> （`handleEdit` → 滚到 `#keyboard-area` → 键盘用该音的 state remount），释义面板随之显示这个字，
> **「谱中见过」本来就在**。真浏览器实测 3 处 · 2 首，布局可读；已固化成
> `scripts/verify-score-concordance.mjs`（这条路径没有任何自动测试盯着）。

## 十八、减字谱数字化的学术谱系（1989 → 2010）：我们不是第一个做编码的

> 情报时间：2026-11-07。触发来源：公众号「吉善居琴馆」2020-07-30 转载《古琴减字谱的编码与编辑方法》，
> 正文是论文扫描页，公众号文章本身抓不到文字。
>
> 信源分级：
> - **一级（同文全文）**：core.ac.uk `41348479.pdf`，《中国音乐学》2008 年第 2 期，文章编号 1003-0042(2008)02-0093-04；
>   另有 audioapp.cn 转录本，两处互校一致
> - **二级（专利摘要）**：《一种古琴减字谱的计算机生成、编辑方法与系统》（天眼查专利页）——该页把丁晓君等论文当
>   **现有技术**引用，所以发明人**未必**是同一批人，本文按「另有一件专利」处理
> - **二级（科普页）**：钧天坊「減字譜」条目（指法符号 1000 多个的说法出自这里）

### 18.1 一句话：这不是新对手，是要改口径

它证明「减字谱编码」这件事，**1989 年就有人做，2008 年已经做到「表达式 + 分析树 + 自造字库 + 可编辑软件」**。

所以 `pitch.md` 4.1 那句「减字文本码——对手都没有」，**在产品层面仍成立，但经不起懂行的人追问**。
改法见 18.6。

### 18.2 时间线

| 年 | 谁 | 做了什么 | 今天看它的意义 |
|---|---|---|---|
| 1989 | 陈长林（中科院计算所研究员、古琴闽派传人） | 《电脑在古琴音乐研究中的初步应用》，《计算机学报》 | 最早的减字计算机生成；2008 年论文自评「对『撮』这类复杂结构支持不足」 |
| 2003–04 | 张维城、苏文钰（台湾成功大学） | 《古琴减字谱数位系统》，2003 资讯科技与图书馆学术研讨会论文集 | 编码方案的直接前身 |
| 2007 | 潘知枭、周昌乐 | 《基于古琴减字谱图像的文本切分与提取》，《心智与计算》 | **整页切分 / 识别的第一个脚印** |
| **2008** | 丁晓君、叶婷、周昌乐（厦门大学信息科学与技术学院 艺术认知与计算实验室） | 本文：五部分结构 + `+`/`*` 表达式 + 二叉树 + 自造字库 + MFC 编辑器 | 与我们空间模型同构的那一代实现 |
| 2010 | 佚名（同期《计算机工程》） | 《Windows 下处理减字图形之新方法》 | 支持「撮」结构，但自评「处理速度慢、实用效果不理想」 |
| 2010s | 一件专利 | 部件 → 自造字 Unicode 码值串 → 四象限显示区域 → 把谱字信息存进**图片描述字符串**以便再编辑 | 它的数据载体是「图片 + 隐藏描述」，我们是纯文本 |

### 18.3 他们的方案（五条，逐条对照着看）

1. **结构划分**：上左 = 左手指名，上右 = 徽位，下左 = 装饰（绰/注），下右 = 右手弹法**及弦位**。
   没有左手时（散音），上部缺省、下部移到中间。
2. **两个运算符**：`+` 连接左右手或不相关的两个指法；`*` 连接同一手的指法、徽位、弦序。
   **`*` 优先级高于 `+`**，连接顺序按「从左到右、从上到下」。
3. **转成表达式**：那个典型的字（左大指七徽六分、注挑七弦）= `大*七*六+注挑*七`；散勾七弦 = `散+勾*七`。
4. **再转成二叉树**：`+`/`*` 都是二元运算符、左右不可交换 → 每个结点至多两棵子树 → 直接当内存数据结构，
   便于分析、重构、辅助打谱。
5. **造字库 + 编辑器**：用 Font Creator 造常用减字、**给每个字分配一个编码**、存成字体文件；
   编辑器是 VC6 + MFC + BCG 界面库，四类分组（散音/按音/泛音/其它），
   卖点是「输入一个减字符号，只需要点击鼠标四次」。

### 18.4 和我们重合到什么程度

| 环节 | 他们（2008） | 我们（2026） |
|---|---|---|
| 空间模型 | 上左 / 上右 / 下左 / 下右（弦序在下右） | `svg-paths` 四象限降级 + 字体 GSUB 并置，槽位同构 |
| 部件来源 | 自造字（Font Creator 手造） | 开源字体 `WangJiJianZiPuKaiTi` + 逐字 SVG |
| 机器表示 | 表达式 `大*七*六+注挑*七` / 二叉树 | 减字码 `ad9f6cg4` + `JianziState` 字段 |
| 文本 → 部件 | 汉字意义串按**最长匹配**切分 | `parseJianziText`（这次顺带核对过，同样是最长优先） |
| 数据载体 | 自造字 Unicode 码位（PUA），专利里还塞进图片描述字符串 | 纯 ASCII 文本 / JSON |
| 输入 | 鼠标点选四次 | 键盘点选 + 连打语法 + 整页识别 |

**结论：同一套空间模型的两代实现。** 差别不在「有没有想到」，在**载体**：
他们必须先把字造出来、分配到码位，才能存；我们的码先进任何文本文件，字形只影响「画得好不好看」。

### 18.5 为什么这条路没变成产品（三条，比功能对比有用）

1. **字库路线随 OpenType 生态一起死了。** 整套方案的前提是「每台机器装一份自造字库、每个字占一个 PUA 码位」。
   没装字库，码位就是豆腐块——数据在，但没人看得见。2010 年后中文排版全面转 OpenType（GSUB/GPOS），
   自造字体系没跟上；今天能活的做法是**用连字规则让现有字体拼出减字**，也就是我们走的这条。
2. **输入仍是「点四次」。** 他们把「不用记编码」当卖点，代价是慢。十八年后我们还是同一个问题：
   键盘点选（给不会的人）与连打（给会的人）并存。
3. **图像路线当年被判「技术还不成熟」。** 2008 年论文原话：
   「考虑到目前直接进行减字谱图像输入来分析识别出一个个减字谱谱字的技术还不成熟
   （潘知枭、周昌乐 2007），因此本文暂时不考虑图像输入与分析方面内容的研究实现」。
   **他们绕开的那一步，正是今天我们唯一拿得出手的差异。**

### 18.6 要改的一句对外话术

不能说「没人做过减字编码」——1989 年就有，2008 年就有可编辑的表达式和分析树，2010 年代还有专利。
可以说「**没有一个方案把码做成人可读、可手打、不依赖字库的文本**」：

- 他们的码是自造字码位：换台机器没装字库，看到的是空白或豆腐块；
- 我们的码是 ASCII（`ad9f6cg4`）：进任何文本文件、任何编程语言都能读写，字库只决定好不好看。

一句话版本：**「编码早就有人做，但都要先装他的字库；我们的谱是一行文本，记事本就能传。」**

### 18.7 顺带核到的两个数字（可引用）

- 现存古琴谱集 **140 余种**、不同传谱 **3365 个**、不同传曲 **658 首**（2008 年论文的统计口径）。
- 古代减字谱的各种指法符号 **1000 多个**（钧天坊「減字譜」条目）。
  这两个数字可以回答「曲库要做多大才算全」。

### 18.8 这次核出但未定论的

- 2010《Windows 下处理减字图形之新方法》原文未读（只从专利正文转述知道它支持「撮」、自评慢）。
- 那件专利的发明人与申请人未核（详见本章开头的信源分级）。
- 张维城、苏文钰「减字谱数位系统」（成功大学，2003）未拿到原文。
- **弦序到底标在哪个位置，三套描述不一致**：论文说下右（右手弹法**及弦位**），
  钧天坊条目与丝桐 App「知琴」页都说「中部＝弦数、旁部＝指法」。引用时按论文（下右）为妥，
  被问到别把「中部」指为错——两种措辞指同一个格子（详见 19.4）。

## 十九、丝桐（2018-08）：练习这条路八年前就有人走过，而且免费

> 情报时间：2026-11-07。来源：公众号「度一古琴馆」《古琴首款以练习为主的app上线了！！！》，2018-08-25。
> 一级材料（同文正文）+ 二级交叉印证（西西软件园转载页、cr173 存档页）。
> 现状核实：`7stringedzithers.com` 2026-11-07 实测**无法解析域名**；度一学堂官网 `dyxt.org` 仍在线，
> 但站内已**不再提「丝桐」**（只留一个「App下载」栏目和「古琴调音器App」）。据此判为**停运**，
> 未拿到官方下架公告，故按「域名失效 + 母站不再提」这个强度表述。

### 19.1 一句话：它把「练习侧」的时间线直接推到 2018 年

我们 `pitch.md` 4.2 原来写「播放：他们有试听回放；我们多出慢练、分句、节拍器」。
这句话**对编辑器成立，对练习类 app 不成立**——丝桐 2018 年就有：

| 它在 2018 年就有的 | 我们现在的对应物 |
|---|---|
| **与古琴琴面等比例的展示** | `QinFingeringDiagram`（琴面按点图） |
| **A/B 句定义**，「一个乐句一个乐句练习」 | 分句慢练（`phrase_ranges` + `practicePass`） |
| **延音**，「推荐 0.5 倍」 | 慢练的 `TEMPO_LADDER` |
| **录音回放** | 无 |
| 调音器 / 节拍器 | 有 |
| 曲目「观赏」页：听、下载、收藏、**琴曲介绍**（含定弦标注，如「1=F（E调定弦）」） | 曲谱信息 + 播放 |

也就是说：**「听 + 一句一句练 + 减速 + 看琴面」这一整套，在 2018 年一个免费 iOS app 里就齐了。**
这不是我们独有的能力，是古琴 app 的**及格线**。

### 19.2 它长什么样（当年）

- 形态：**纯 iOS**（iPhone 5 以上，「5.5 英寸显示屏最佳」），安卓「正在狂奔来的路上」——**没等到**。
- 价格：**免费**，试运行期给 5 首：《仙翁操》《秋风词》《凤求凰》《酒狂》《关山月》。
- 结构：底部三个入口 `琴` / `知琴` / `吾`，加一个 `言`（介绍）。
- `知琴` 分三节：**古琴**（琴史）、**手势**（指法图解，如「挑：食指向徽弹出」）、**减字谱**（结构拆解）。
- `琴` 页每首曲子分左右两路：左边「观赏曲目」，右边「开始练习」。
- 主体人群：从「本地找不到老师、教材太厚不好带、节奏把握不好」这三个痛点出发（`言` 页自述）。

### 19.3 三个可以直接用的结论

**① 「以练习为主」这条赛道在这个圈子里没走通。**
它自称「古琴届首款以练习为主的 app」，八年后域名失效。
对照一下：同期做「打谱/录入」的丝桐里（2023-07 上架，注意**比丝桐晚五年**、不是同一家）今天还在跑，
有 291 条评分、4.8 分。**替人「练」的活不下去，替人「写」的活下来了。**
原因不难猜：练习的替代品是**老师**，而钱是付给老师的；打谱的替代品是**空白**，没有别的东西可付。

**② 又一条「用户价格预期是 0」。**
2018 年免费 5 首；2021 年华夏古琴网「永久免费」、琴社入驻也免费；爱搜减字免费。
**这个圈子的用户不认为「工具」该收钱**，付钱的对象是琴、课、老师。
所以我们的「免费网页 + 不做订阅」不是策略选择，是**这个市场的默认值**。

**③ 别把「练习功能」当卖点讲。**
`pitch.md` 4.2 那条已改成限定说法（见 19.5）。对外如果拿「分句慢练」当差异，
对方只要掏出 2018 年的丝桐截图就够了。

### 19.4 顺带核出的一处口径冲突：弦序标在哪

同一个字的四个部位，现在有**三种**说法：

| 来源 | 左手指名 | 徽位 | 右手指法 | 弦序 |
|---|---|---|---|---|
| 丁晓君等论文（2008） | 上左 | 上右 | 下右（与弦序同处） | **下右** |
| 钧天坊「減字譜」条目 | — | — | 旁部 | **中部** |
| **丝桐 App「知琴→减字谱」**（2018） | 左上角 | 右上角 | 旁部 | **中部** |

丝桐的原话是：「左上角：左手指名『大指』／旁部：右手指法『挑』／右上角：徽位『七徽』／中部：弦数『七弦』」。
它和钧天坊一致、与论文不同。**引用时仍按论文（下右）**，但要知道圈内口语说「中部」的不少，
被问到别说人家错——两种描述指的是同一个格子的不同措辞。

### 19.5 要改的一句

`pitch.md` 4.2 原文：

> **播放**：他们有试听回放；我们多出慢练、分句、节拍器。

改成限定版（对手 = 编辑器 / 在线 SaaS），并明确承认练习类 app 早就有一套：

> **播放**：对**编辑器/在线 SaaS**（丝桐里、灵弦），我们多出分句慢练与节拍器。
> 但对**练习类 app** 来说这套是及格线——2018 年的丝桐就有琴面等比例图、A/B 句、0.5 倍延音、录音回放，且免费。
> **它不是我们的差异点，是我们的入场券。**

### 19.6 未定论的

- 「丝桐」与「丝桐里」**不是同一主体**（丝桐：北京度一琴馆关联的丝桐科技，hi@7stringedzithers.com；
  丝桐里：合肥若叶无间网络科技有限公司，开发者「秀英 张」）。但两者名字都取自「丝桐」（琴的别称），
  **对外提及时必须写清是哪一个**，否则听众会混。
- 丝桐的真实下架时间与原因未核（只有「域名失效 + 母站不再提」两个间接证据）。
- 那 5 首曲目之外的付费/会员机制：文中「`吾` 进入会员界面」只提到改头像/名称/邮箱/地址与意见反馈，
  **没提价格**，与「试运行免费」一致，无法确认后来是否收费。

## 二十、包松平 2015 自述的字库数字：我们的「字全」从来没有资格说

> 情报时间：2026-11-07。来源：公众号「包松平 古琴减字谱输入法」同名文章，**2015-12-07**。
> 这是**产品方自己发的介绍文**（一级材料），不是第三方转述。数字都是他自己给的，未经核验。
> 产品档案见 13.2；他 2015 年那篇论文《古琴减字谱数字化初探》的路线记录另见会话记忆（造字库 → 写 IMF）。

### 20.1 他 2015 年报的账

| 项 | 数量 | 备注 |
|---|---|---|
| 基础指法减字 | **近 1500 个** | 自述「存见古今的各种基础指法减字」，**包含各种异体字与上古声曲折谱符** |
| 指法名称用字 | **近 500 个** | 「多数能在 GBK 字库中找到，补充了 GBK 没有收集的古琴方面的字」 |
| 演奏手势图 / 琴体部位图 / 音律图 | **200 多个** | **也做成了字库里的字符**（不是插图） |
| 组合输出 | 「已达**数百万字**」 | 左手 / 右手 / 复合结构的正字（大字）与旁字（续部小字） |
| 覆盖 | 「**已基本覆盖《琴曲集成》全 30 册**中的各种结构样式减字」 | 这是他给的能力边界，也是行业里唯一可比的覆盖指标 |
| 录入速度 | **每分钟约 30 个**减字 | 自述「像在电脑上打汉字一样」 |

### 20.2 对照我们自己的账

| | 包松平（2015） | 我们（2026-11 实测） |
|---|---|---|
| 字形存量 | 约 2200 个字形（1500 减字 + 500 用字 + 200 图） | 字体 `WangJiJianZiPuKaiTi.ttf` **471 个字形**；SVG 降级 **77 个部件**（徽 13 / 右手 26 / 弦 7 / 左手 4 / 分 4 / 装饰 21 / 起首 2） |
| 计量单位 | **整字**（每个字一个 PUA 码位） | **部件**（整字靠并置拼出，没有整字表） |
| 组合方式 | 特殊算法组合，输出数百万字 | 字体 GSUB 并置 / 四象限 SVG 拼装 |
| 异体字 / 上古声曲折谱符 | **有**（明确列出） | **没有**（一个都没有） |
| 覆盖统计 | 有（对应《琴曲集成》30 册） | **从来没做过** |
| 录入速度 | 30 字/分（自述） | **没测过** |

以上数字由 `apps/web/scripts/inventory-glyphs.ts` 现场跑出（可复跑、带退出码闸门）：

```
字体字形（maxp.numGlyphs）   471
SVG 降级部件                 77
  分组                       fen:4  hui:13  lh:4  rh:26  str:7  top:2  mod:21
示例谱                       4 首 / 71 个音
示例谱里不同的减字            27 个
```

最后一行值得停一下：**我们内置的 4 首谱加起来，只用到 27 个不同的减字。**
这就是目前全部「实测过的覆盖」。拿 27 去对「《琴曲集成》30 册」，不需要讨论先进与否。

**另外，我们连「多少个字」这个问题都得换一种问法。** 他数整字，我们只有部件——
「我们字库有多少字」在我们这里没有对应答案，因为整字是拼出来的、没有清单。
能回答的只有「**拿一本谱来试，能拼出多少**」，而这个实验一次都没做过。

**这三行空白（异体字、覆盖统计、速度）是真差距，不是「我们路线更先进」能盖掉的。**

我们的模型确实不同：他用「整字 + PUA 码位」，我们用「部件 + 并置」，理论上组合不受字形数量限制。
但**「理论上无限」和「实际覆盖多少首古谱」是两件事**——前者是架构话术，后者要一首一首数。
到今天为止，我们没有数过。

### 20.3 一条必须收的口径

不能说，也不该暗示：

> ❌「什么古谱都能打进来」／「字库很全」／「覆盖了传世琴谱」

正确的是：

> ✅「常见指法都能打。**罕见的异体字、上古声曲折谱符我们现在没有**；
> 具体的覆盖范围我们还没统计过——这是我们下一件该做的事。」

对外如果被行家追问「你这字全不全」，答「不知道，我们没数过，正在数」比硬答「全」安全得多。
**这个圈子小到有人能拿一本《琴曲集成》逐页对**（华夏古琴网那次已经证明过）。

### 20.4 值得抄的两个做法

1. **把「覆盖多少册/多少首」当产品指标公开。** 他 2015 年就用《琴曲集成》30 册当尺子。
   我们现在连自己曲库能覆盖几首都没数——这是一件**纯统计、零风险、能直接写进对外材料**的事。
2. **录入速度是可以量化的。** 「30 字/分」这种数字一给出来，比「方便快捷」有力得多。
   我们的连打语法（`ad9f6cg4` = 大九六分绰勾四）理论上更快，但**没测**——测一次就有数字。
   测法很直白：给一段 100 字的谱，计时打完，换算成字/分。

### 20.5 未定论的

- 那 1500 个减字与 200 多个图，是**真的都有独立字形**，还是「部件 + 组合规则」被表述成「字数」？他写「存见古今的各种基础指法减字……字数近 1500 个」，
  按字面是字形数，但「通过特殊算法组合成……数百万字」说明他也有组合层。**两层的边界没写清，引用时别把 1500 当成「整字总数」去对比别人的整字数。**
- 「上古声曲折谱符」具体收了哪些、依据哪本谱，文中未说。
- 该版本是否为免费、如何获得：本文只讲功能，**没提价格与获取方式**（13.2 记的是后来「免费发布、一人一码」）。
