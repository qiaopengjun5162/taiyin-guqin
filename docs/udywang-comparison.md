# 对标分析：udywang.com（王悠荻 · 古琴 Guqin 站）

> 分析方式：浏览器 CDP 实访，提取 DOM 结构 + 拉取并精读核心 JS（`home-qin-preview.js`、`guqin/open-string-samples.js`）+ 正文。
> 注：页内多个 canvas 持续 rAF 动画，CDP 截图超时，以下结论基于 DOM/JS/正文，非截图。

## 1. 它是谁、做什么
- 古琴演奏家王悠荻个人/数字艺术站（哈佛访问学者、中国首位古琴演奏博士）。
- 三大核心功能（hero 入口）：**虚拟古琴** / **古琴习曲** / **古琴调音器**。
- 两件数字艺术作品：
  - 「琴与人的交互 1 号」：用 **AI 图像识别** 把"减字谱 → 古琴音乐"转化，邀请观众参与（中央音乐学院，曾展于亚洲数字艺术展等）。
  - 「探索与回望：琴」：视听联觉 + 观众动作交互 + 古琴音乐反馈的沉浸空间（canvas 粒子 + 3D 房）。

> **署名勘误（据《2023 中国人工智能系列白皮书·AI+Art》，P146-147，图 2-84）**：
> 该作品白皮书署名 **魏冰（2021）**，并非 udywang.com（王悠荻）站点所有。三方协作关系为：
> **魏冰**（作品作者）/ **王悠荻**（站点与演奏）/ **王慧敏**（截图角注「古琴音乐由王慧敏录制」）。
> 白皮书原文定位："作品利用人工智能图像识别算法，通过多媒体交互的方式，邀请观众参与到从古琴减字谱到古琴音乐的转化过程当中来……作品所呈现的琴与人之间交互结果的多样性，具有**包容性、可解释性和一定程度的随机性**。"
> 这三个特质（包容 / 可解释 / 随机）正是我们实现"AI 识别减字谱"时可对照的设计准则——我们把"AI 误读"做成**教学对照**（AI 读作 X、公认该是 Y），而非他们的艺术价值本身。

## 2. 技术实现拆解（重点：虚拟古琴）
- **栈**：原生 JS + ES Module + Canvas2D + Web Audio + goober（CSS-in-JS），**无 React/Next/three.js**，纯静态轻量。
- **可玩古琴**（`virtualQin` = 内含 SVG 的 `<button>`，viewBox `0 0 100 100`）：
  - 七弦 Y 坐标 `[33.70, 42.64, 50.60, 58.29, 66.01, 73.73, 81.45]`（百分比）。
  - hover / click → `stringAt()` 取最近弦（阈值 7%）→ 拨响；支持复音。
  - 全局 `pointerdown/touchend/keydown`（capture）解锁 AudioContext，规避自动播放限制。
- **音频架构**（关键参考点）：
  - 用**真实散弦录音**（王悠荻演奏）：48k/24bit 单声道 → 切 4s → 升余弦自然淡出 → **A 加权响度归一** → 四弦单独补 2dB → AAC 80k。
  - 七弦音准 **±8 音分**，正调 **C2 D2 F2 G2 A2 C3 D3**。
  - 按弦**懒加载**（`new URL('./audio/open/sN.m4a', import.meta.url)`），掠到哪根取哪根。
  - Web Audio 链路：`source → gain(0.658 预听) → bus(0.92) → DynamicsCompressor(限幅) → destination`。
  - 复音：`voices` Map，重触发时对旧音 `setTargetAtTime(0.0001, 0.04)` 淡出再 stop。

## 3. 与我们 taiyin-guqin 的逐项对比
| 维度 | udywang.com | 我们 taiyin-guqin |

| 古琴发声 | 真实录音采样（7 个 m4a） | Karplus-Strong 合成（零素材依赖） |
| 减字谱 | 艺术/AI 识别"解读" | 结构化录入 + 字体 GSUB 渲染 + SVG 降级 + 复合指法 |
| 交互 | 可玩古琴（拨弦）、调音器、习曲、沉浸艺术 | 录入键盘、乐谱流、歌词、播放/调速/音色、WAV/PNG/SVG 导出、歌词跳转、自动滚动、空格播放 |
| 定位 | 个人品牌 + 数字艺术展品 | 古琴减字谱创作/学习工具 |

## 4. 值得借鉴的点（按性价比排序）
1. **古琴调音器**（我们缺的模块）：以正调 C D F G A c d 为目标音，做音高检测 + ±音分显示。与我们的 Web Audio 栈直接复用，价值高、成本中。
2. **主链路加限幅总线 + 响度归一**：他们显式用 `DynamicsCompressor` 限幅，并对各弦做 A 加权响度归一（低频弦本就需要更大振幅才"听着一样响"，四弦还补 2dB）。我们合成音色也应加一条 master 限幅总线，并对七弦/散按泛做**感知响度对齐**，否则低音弦会偏弱。
3. **可玩"虚拟古琴"拨弦视图**：作为录入/试听之外的第三交互层——SVG 七弦 hover/click 发声，复用我们的 Karplus-Strong 按弦发声。教学与趣味性强。
4. **AudioContext 解锁 + 按弦懒加载模式**：我们已有播放解锁；可借鉴其 capture 阶段全局解锁 + 按需取音频，降低首屏负担。
5. **"减字谱 → 试奏"参与式交互**的思路（非艺术展陈外壳）：可启发一个"点减字即试听该音"的轻量模式。

## 5. 我们的差异化优势（不必抄）
- **合成而非采样**：零素材依赖、可离线、音色可参数化（散/按/泛），适合做 Web 工具；可把"真实录音音色包"作为**可选下载**叠加，二者兼得。
- **减字谱创作能力**：录入键盘 + 歌词 + 多格式导出是我们的强项；对方偏"消费/艺术"，不涉创作。
- **框架选型合理**：对方用原生是为了静态艺术站；我们 Rust+Next 的结构化数据/服务端/LLM 集成对"工具"定位更合适，无需切换。

## 结论
最该立刻做的是 **古琴调音器** + **主音频链限幅/响度对齐**；其次是 **可玩虚拟古琴拨弦视图**。音色上"合成 vs 真实采样"两条路不冲突，可并存。
