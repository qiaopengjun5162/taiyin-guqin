## 4. 卡点与解决

- **现象 1**：预备拍用例断言「9 个点击声」，实际只有 8 个。
  - **误判**：以为节拍器循环少跑一拍。
  - **定位**：手算音轨长度 `ceil((leadIn 4s + 旋律 3s + 0.3s) × 44100)`，即 7.3s；
    第 9 个拍点 `t = 0.05 + 8 = 8.05s`，`t < length/sampleRate` 为假，被 `if` 裁掉。
  - **根因**：不是 bug，是测试算错了（把「旋律 4 拍」当成 4 秒，但休止符 toneType 为 null → tail 0.5 而非 2.0）。
  - **改法**：把断言改成 8 个 + 8 个重音位，并在注释里写清「第 9 拍被裁掉」的原因。

- **现象 2**：节拍器用例断言 `stopMetronome` 被调用 1 次，实际 0 次。
  - **定位**：读 `page.tsx` 发现按钮 `onClick={toggleMetronome}` 始终是 toggle，
    只有 `aria-label` 随运行态变（`启动节拍器` ↔ `停止节拍器`）。
  - **根因**：把「按钮文案」当成了「按钮语义」。这是 UI 的既定设计（同一个键开/关）。
  - **改法**：改成断言 `toggleMetronome` 调 2 次、`stopMetronome` 0 次，并注明原因。

- **现象 3**：保存成功断言 `getByRole("button", { name: "已保存" })` 超时。
  - **根因**：`aria-label="保存"` 固定，可访问名不随文本变；`saveStatus` 只体现在 `textContent`。
  - **改法**：`expect(saveBtn.textContent).toBe("已保存")`。

- **现象 4**：撤销一次后音符还在（8 条没归零）。
  - **定位**：`handleLoadExample` 先 `commitScore`（换音符）再 `commitScoreTitle`（换标题），
    是两次独立提交 → 需要 Z 两次。
  - **改法**：测试按真实历史栈撤两步，并顺带验证 redo 能回到 8 条。

- **顺带修掉一个真 bug**：拼音模式提交「纯拼音」（如 `da gou`、未选候选词）时，
  `parseJianziText` 返回 null 而旧代码写成 `parsed ?? createEmptyState()`，
  于是往谱面追加一个**全空的谱字列**——乐谱里出现一个点不响、删不掉的空音。
  改成解析失败直接 return（不清输入，让用户继续选候选），并加了回归用例。

- **变异验证**（纪律要求「新测试必须亲手看它红一次」）：
  1. `jianzipu-keyboard.tsx` 把 `value === "散"` 改成 `"__mutated__"` →
     `AssertionError: expected '大' to be null` ✅ 红
  2. `audio-export.ts` 把 `s.start + startOffset` 改成 `s.start` →
     `AssertionError: expected +0 to be 4` ✅ 红
  3. `page.tsx` 把 `leadInBars: exportWithCountIn ? 2 : 0` 改成 `0` →
     `AssertionError: expected { beatsPerBar: 3, …(2) } to deeply equal {...}` ✅ 红
