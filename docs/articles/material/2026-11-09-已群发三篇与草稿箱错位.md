## 二、错在哪

判定依据只有一样：`Articles/ready/<slug>.media_id` 文件存在。但那个文件只证明
**「这篇文章被 push 进过草稿箱」**，它不区分「草稿箱里躺着」和「已经群发出去」。
微信后台的群发动作不写回任何本地文件，`list-drafts` 也因为缺 `WECHAT_SECRET` 跑不了。

所以链路是：

```
改稿 → just render → 推前门禁(绿) → just push → 新 media_id → 后台旧草稿被删
                                                      ↑
                                    线上那篇：完全不受影响
```

`push` 的语义是「替换草稿箱里的那一份」，不是「更新已发布文章」。这一点 moonpub 的输出里
写得很清楚（`pushed to WeChat draft` / `deleted old draft`），但我在上一轮把它读成了「更新成功」。

## 四、为什么「改草稿」到不了线上

| 动作 | 是否影响线上 | 说明 |
|---|---|---|
| 改 md | 否 | 只改本地源稿 |
| `just render` | 否 | 只重生成 html / draft.json |
| `just push` | **否** | 替换草稿箱那一份，换 media_id，旧草稿删除 |
| `just update-draft` | 否 | 只改草稿；且本机缺 `WECHAT_SECRET`，跑不了 |
| 后台「修改」 | 是 | 已群发正文可改，但字数/次数限额很严（约 20 字、一次），**以后台实际提示为准**；标题不可改 |
| 删除重发 | 是 | 会丢阅读数、留言、已扩散的分享链（旧链接变「该内容已被发布者删除」） |

## 五、本轮仍然成立的产出

1. **推送前门禁加固**：`bundle_hygiene` 里的相对路径图从「警告」升成**无条件阻塞**。
   依据是 `push.rs:349-400` 的 `upload_local_images` 只在 appsecret/token 模式执行，
   cookie 模式走 `push_browser.rs` 根本不上传，`src="fig/x.png"` 必然破图。
   自测 55/55，两条变异实测变红。存量受影响：`verification-that-can-fail`、
   `engineering-as-research`（各 3–4 张）现在会被拦并给出修复方向。
2. **摘要修正**：旧摘要 152 / 163 字，被 moonpub 按 **120 字节**截断成半句
   （实测截断点恰好 119 bytes，例如「…37554 行」／「…今天有了公开地址：」）。
   已改成 106 / 111 字节的完整句。见下方「上游 bug」。
3. **台账语义修正**：新增 `published` 的真实使用；扫描范围从「只扫 pending」扩到
   「pending + published」—— 已群发的稿子仍可能被重推，不能因为「发过了」就脱离闸门。
4. **证据固定**：render 只改 frontmatter 的 digest 时，html 与旧稿**逐字节相同**
   （还原 7 个 `src` 后断言通过）。这条可用来区分「摘要变了」和「正文变了」。

### 上游 bug（未修，仅记录）

`moonpub` 源码 `src/render.rs:269-275`：

```rust
// WeChat digest limit is 120 chars; truncate at a char boundary.
let mut end = 120usize.min(digest.len());   // ← 120 是字节，不是字符
while !digest.is_char_boundary(end) { end -= 1; }
&digest[..end]
```

注释写「120 chars」，代码按 120 **字节**切。中文 3 字节/字，实际只给 40 个汉字，
且必然切在半句。WeChat 文档的上限是 120 **字符**。修法是把 `digest.len()` 换成
`digest.chars().count()` 并按字符边界截断（或直接用 `char_indices`）。
本机 `moonpub 0.4.8` 与源码 `0.4.13` 行为一致，本次**没有改它**——那是全局工具，
影响全部 79 篇的推送路径，需要单独一轮带测试改。

## 六、决定与后续纪律

**已定（2026-11-09）**：线上三篇**先不动**，只记录；草稿箱两篇（`100018567` / `100018575`）
留作新口径母版，不删不改。

**纪律**：

1. 推送前先核「是否已群发」，不要只看 `.media_id`。可核的信号只有三个：
   公众号后台的「已发表」列表、文章的 `mp.weixin.qq.com/s/...` 链接、以及历史群发记录。
2. `media_id` 只能证明「进过草稿箱」。台账里必须写 `published` 并附 mid 与时间。
3. 已群发稿再改，只有三条路：后台有限修改、发更正说明、删除重发。都不等于「改草稿」。
4. 检测手段要留回环：这一轮的结论（线上已发）来自 `WebSearch` + 公众号页面元信息，
   不是来自本地文件——本地文件在这件事上是**无信息**的。
