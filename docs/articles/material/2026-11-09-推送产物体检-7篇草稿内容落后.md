## 4. 卡点与解决

- **现象 1**：门禁连跑几轮全绿，但草稿箱里的稿子和源稿对不上。
- **误判**：「口径已经改完了，剩下的是内容问题」。
- **根因**：判据用了 `p.returncode == 0`，而那个命令**退出码恒为 0**。
  更糟的是自测把 `MOONPUB_GATE_SKIP_PREFLIGHT=1` 硬写死在两个 runner 里，
  第 4 项**从未被执行过一次** —— 坏了两轮都没人发现。
- **改法**：改读 `--json` 的 `passed` 字段（JSON 解析失败再回落解析首行文本），
  自测改成「跳过与否是显式参数」，并用假二进制把 passed=true / false / 只有
  digest_limit 三种情形都测到。

- **现象 2**：`just push` 明明改了 md，推上去还是旧的。
- **根因**：`push` 只读 html，`push` / `update-draft` 都不 render。`--render` 也救不了——
  它只在 `draft.json` **缺失**时才生效，存在就是空操作。
- **改法**：新增 `bundle_fresh` 检查，`md > html` 直接判红并给出 `just render` 一行命令。
  **刻意不自动 render**：render 会把手工替换过的 CDN 图链接和二维码冲回相对路径 +
  200KB base64，那是上一个坑。

- **现象 3**：加完 preflight 真判后，三篇待发稿里两篇被拦。
- **定位**：`digest_limit: digest exceeds WeChat 120-char limit (152 / 163 chars)`。
- **判断**：这不是推送故障 —— push 会按字节把摘要截断到约 69 字写进 draft.json，
  微信端显示正常。属于「源稿摘要偏长」的内容质量问题。
- **改法**：给 preflight 的失败项分级，`TOLERATED_PREFLIGHT_FAILS = {"digest_limit"}`
  降级为 warn；`image_links` / `layout_audit` / 文件缺失 / 标题超长仍阻塞。

- **附带修正**：`cover_matches` 在 cookie 模式下要求 `thumb_media_id` 指向本文，
  但 cookie 模式**根本不读这个字段**（直接找 `<slug>.cover.png`）。这是「对的结论、
  错的依据」，还导致每推一篇都要先切全局封面。改成按 `auth_method` 分支。

### 变异验证（两条，实测红）

```text
变异1 preflight 判据退回 returncode → 用例 10/12 失败（preflight=pass，rc=0）
变异2 新鲜度 > 改成 >=              → 用例 14 失败（同秒被判旧）
```

第一次跑变异时副本放在 `/tmp`，`import wxlib` 失败 → 全部用例崩溃 → 看起来「抓到了」。
那是**假抓到**：变异脚本改成检测 `Traceback` 并把副本放进 `scripts/` 同目录后才成立。
