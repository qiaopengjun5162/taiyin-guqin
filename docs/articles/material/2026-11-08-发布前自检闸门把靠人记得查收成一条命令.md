# 发布前自检闸门：把「靠人记得查」收成一条命令（2026-11-08）

## 意图

上一轮三道门全卡在人或素材（群发要人点、真机要人拿手机、真谱要照片），用户回「继续」。
这轮挑一件不等人、又直接服务「出门」的事。触发点是上一轮那个事故：`build` **连红四次**
（11-07 傍晚起）却被 Pages 部署成功盖住——根因不是没人会查，是**全靠人记得手工查**。
文章马上群发，两个试玩链接、CI、门面文案，每一样之前都是我一轮一轮手工核的。

目标：把这些检查固化成一条有退出码的命令，且闸门自己必须能被验证（不能是恒绿摆设）。

## 输入

- 事故记录：`CHANGELOG.md` [0.40.3]、`docs/articles/material/2026-11-08-CI连红四轮没人发现-识别面板藏掉了试听按钮.md`
- 项目已有闸门风格：`apps/miniprogram-wasm-probe/scripts/precheck-real-device.mjs`（双模式）
- 两个线上入口：GitHub Pages `qiaopengjun5162.github.io/taiyin-guqin/`、Vercel `taiyin-guqin-alws.vercel.app/`
- 环境坑（长期记忆）：沙箱代理 50218 会让直连 502；`*.vercel.app` 要走本机 Clash 7890


## 卡点

- **最容易误判的是「chunk 文件名不同 = 版本不同」**。静态 SPA 的正文不进 HTML，
  curl 看不到组件；构建平台不同会让 hash 全变。判断版本只能看**可观察行为**，
  不能看产物指纹。
- **闸门自身要能自举验证**：`--self-test` 把旧门面 / 单个 failure 喂进纯函数，
  必须得到相反结论；再加一次「未提交文件」的真实 FAIL，才敢说它不是恒绿。
- **CI 项必须逐个列出当前 headSha 的所有 workflow**，只看部署那一个 = 复刻四连红事故。
  仍在跑的标 PENDING（WARN），不误判成 FAIL。
- 代理坑跨环境：脚本自动剔除指向 50218 的沙箱代理变量，Vercel 走 `VERCEL_PROXY`
  注入；不把本机 IP 写死成唯一路径，换台机器仍可用。
- `--browser` 依赖 playwright，缺了只 WARN 不阻塞轻量档——闸门不能因为「少装一个包」
  就整个不可用。

## 结论（可引用）

- 「靠人记得查」不是流程，是运气。四连红的根因不是不会查，是**没有一条会自己跑、
  会返回非零退出码的命令**。
- 「部署成功」不是质量信号：`build` 与部署并行，部署可以吃旧产物。
- 判断两个站点是否同版本，比「行为」不比「文件名」；真浏览器点一下，比读十行 chunk 强。
- 闸门要分档：轻量档天天能跑，真浏览器档发布前跑；必带 `--self-test`，
  否则闸门会悄悄退化成一个永远打印 ✅ 的脚本。
