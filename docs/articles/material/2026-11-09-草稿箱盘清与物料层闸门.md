## 4. 卡点与解决

- **现象 1**：`checkCopy()` 一直绿，但草稿箱里的待发稿整节在讲「拍照识别」。
- **误判**：「口径已经改完了」—— 其实只改了白名单里的 5 个文件。
- **根因**：白名单写死路径，`docs/articles/drafts/` 从来没进过扫描范围。**机制缺口，不是文案缺口。**
- **改法**：判定逻辑抽到 `scripts/lib/copy-gate.mjs`（纯函数，才能做变异验证）；
  `verify-publish.mjs` 新增 `--copy-only` / `--vault`；台账 `pending-copy.json` fail-closed；
  CI 加一步 `Verify pending article copy`。

- **现象 2**：想原地改稿保编号，`moonpub update-draft` 直接拒绝。
- **误判**：以为 `--thumb` 能一起切封面（实际不接受该参数）。
- **根因**：`update-draft` / `list-drafts` / `delete-draft` 都要 `WECHAT_SECRET`，**本机全机没有**。
- **改法**：回退 `push`（换 media_id、旧稿自动删）。这条边界写进报告，不假装能原地改。

- **现象 3**：`push` 打印 `✓ done`，但正文 226KB、6 张图变成 `fig/xxx.png` 相对路径。
- **误判**：「推成功 = 推的是新版」。
- **根因**：moonpub `render` 把页脚二维码内联成 ~200KB base64，配图渲染成相对路径；
  微信正文里相对路径就是破图。push 日志不校验这些。
- **改法**：复用已上传的微信 CDN 链接（`mmbiz.qpic.cn`）替换相对路径 + 二维码；
  新增 `verify-article-bundle.mjs` 把「无 base64 / 无相对路径图 / 体积上限」变成断言。
  结果：25.7KB / 8 张 CDN 图 / 0 base64。

- **现象 4**：5-months 修图脚本跑完 html 变 0 字符。
- **根因**：`open(hp, "w")` 先清空文件，后面的断言才抛异常。
- **改法**：改成「先用 `transform()` 算完全部结果、断言通过后才写盘」。这条对以后所有批处理脚本都适用。
