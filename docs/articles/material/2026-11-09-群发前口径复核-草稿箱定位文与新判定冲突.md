→ **修法**：以 `md` 为唯一权威源重新 `moonpub render`，让 md / html / draft.json 三源全是新口径，
推送前逐个核对；**不要只改 draft.json**。推送后也要复查 draft.json 有没有被写回旧内容。

**坑 2：`render` 会把「入阁二维码」内联成 200KB base64，而旧稿那张图已是微信 CDN URL。**
新渲染正文从 28KB 涨到 229KB，多出来的正是 `data:image/jpeg;base64,...`（201,156 字符）。
→ **修法**：从备份的旧 draft.json 提取那张图的 CDN URL，把 html 与 draft.json 里的 base64 换回，
正文回到 29,012 字符、2 张 CDN 图、无 base64，与 11-08 成功推送的形态一致。

**坑 3：直接调 `moonpub push` 时 cwd 不在 vault 根 → 读不到 `.moonpub/preview_to`，预览被静默跳过。**
`just push` 会以 justfile 所在目录为工作目录，所以 11-08 能记住接收人；直连 moonpub 则找不到。
→ **修法**：在 vault 根运行，并显式带 `WECHAT_PREVIEW_TO=qpj4812701762`（双保险）。
另：iCloud 路径下 zsh 会刷 `command not found: _encode/_decode`（GVM rc 噪声），**exit 0 且预览成功，无害**。

### 8.3 可复现校验

推送前对 md / html / draft.json 三源各查 6 条旧口径 + 5 条新表述 + `data:image` 计数，
`VERDICT: ALL_OK`；推送后复查仍是新口径。备份留在
`/tmp/wb-moonpub-bak-20261109/`（旧 html/draft.json/media_id/md）与
`/tmp/wb-patched-draft.json`（补丁版），可随时回退。
所用脚本：`/tmp/wb-sync-vault-v12.py`、`/tmp/wb-patch-draft-v12.py`、
`/tmp/wb-restore-cdn-image.py`、`/tmp/wb-check-paste-list.py`。

### 8.4 纪律（写给下一次改公众号草稿）

1. **md 是唯一权威源**；改完先 `render`，推送前**必须三源核对**，推送后**再核对一次**。
2. 别只改 `draft.json` 就以为生效——`polish` 会从 html 重建它。
3. 每次 push 都会**删上一份草稿并换 media_id**；只想补预览时用正确 cwd + 显式接收人，别盲目再推。
4. 预览成功后核一遍手机上的实际内容；「push 输出全绿」不等于「推的是新版」。
