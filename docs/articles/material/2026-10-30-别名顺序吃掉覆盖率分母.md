## 4. 卡点与解决

- **现象**：写 10 条 WASM 桥接测试时，`import("@/wasm/taiyin_core")` 报
  `Failed to resolve import "@/wasm/taiyin_core" ... Does the file exist?`。
- **误判**：先以为是 `vi.mock` 动态导入拦不住、或是 wasm/ 目录没构建。实际上目录在、mock 写法也对。
- **定位过程**：报错来自 vite:import-analysis（连解析都没过，还没到 mock 那步）；
  对照 `tsconfig.json` 有 `@/wasm/* → ./wasm/*`，但 vitest 的 `resolve.alias` 是**对象**写法：
  `"@"` 排在 `"@/wasm"` 前面，前缀匹配先命中 `"@"`，把 `@/wasm/taiyin_core`
  翻译成了不存在的 `src/wasm/taiyin_core`。Next.js 走 tsconfig paths（更长的模式优先）没这问题，
  只有 vitest 中招。
- **根因**：别名匹配顺序。连带后果：该文件在所有测试里都加载不了 → 从没被测过 →
  覆盖率工具拿它做 uncovered-file 归集时解析 TS 失败 → **静默剔除**，分母少 129 行。
- **改法**：
  1. `apps/web/vitest.config.ts`：alias 改数组形式，`/^@\/wasm\//` 排在 `/^@\//` 前面；
  2. 新增 `src/lib/__tests__/taiyin-wasm.test.ts`（10 条：幂等/并发去重/失败重试/非 Error 包装/
     翻译透传/hook 状态流转），文件一旦被测试加载，覆盖率工具自然能解析；
  3. `eslint.config.mjs` 加 `coverage/**` 忽略 + lint 脚本改 `--max-warnings 0`，
     让 warning 也红——CI 之前的 lint 步骤等于只拦 error。

## 5. 结论与可引用点

- 数字：前端行覆盖 **94.44%**（1276/1351），26 文件 298 条用例；
  `taiyin-wasm.ts` 97.91%、`page.tsx` 91.78%（此前 79.86%）。
  阈值抬到 行 92 / 语句 89 / 分支 83 / 函数 88。
- 可以直接进文章的句子：
  1. 「覆盖率工具报 `Failed to parse … Excluding it from coverage` 时，它悄悄把整个文件
     从分母里删掉了——你看不到 0%，只看到一个虚高的百分比。」
  2. 「vitest 里 `alias` 是按顺序前缀匹配的，`"@": ./src` 排在 `"@/wasm"` 前面，
     就会把 `@/wasm/taiyin_core` 解析成 `src/wasm/taiyin_core`（不存在）。」
  3. 「lint 的 warning 从来不会让 CI 变红，直到我们把 `--max-warnings 0` 写进脚本。」
