# 2026-10-29 · 测试覆盖率体检：发现一个「永远绿灯」的假闸门

## 触发

用户原话：「测试覆盖率如何了 要验证的 不要写了很多没有验证大家都没有办法使用」

不是问「有没有测试」，而是问「这些东西到底验证过没有、能不能用」。所以不能答「有 189 个测试」了事，
必须把覆盖率真跑出来，并且证明这些测试**会红**。

## 输入 / 环境

- 本机 macOS，`cargo-llvm-cov` 已装（`/opt/homebrew/bin/cargo-llvm-cov`），`cargo-nextest` 已装
- 本地 Postgres：`postgres://taiyin:taiyin_dev@localhost:5432/taiyin`（sqlx 编译期要连库）
- 前端 vitest 4.1.7，原本**没有** `@vitest/coverage-v8`

## 关键发现 1：CI 的 coverage job 是个摆设

```
$ sed -n '75,103p' .github/workflows/build.yml
  coverage:
    # 非阻塞：覆盖率仅作可视化与基线追踪，任何步骤失败都不应让整体 CI 变红。
    ...
      - name: Install Rust
        continue-on-error: true
      - name: Generate coverage (lcov)
        run: cargo llvm-cov nextest --lib --lcov --output-path lcov.info
        continue-on-error: true
```

每一步都挂 `continue-on-error: true`。也就是说：**这个 job 存在了好几个月，从来没有失败过，也不可能失败**。
覆盖率只是被上传成 artifact，没人看，也不拦任何东西。这比「没有覆盖率」更糟——它给人一种「我们有覆盖率」的错觉。

## 关键发现 2：本机只跑了 5/21 个测试文件

```
$ ./node_modules/.bin/vitest run
 Test Files  5 passed (5)
      Tests  45 passed (45)
      Errors  14 errors      ← 退出码 1
```

14 个文件报 `Failed to start forks worker / Timeout waiting for worker to respond`。
**不是测试失败，是 worker 起不来**（本机内存压力）。试过 `--pool=threads` 同样失败。

最终有效解法：

```
$ ./node_modules/.bin/vitest run --no-file-parallelism --maxWorkers=1
 Test Files  19 passed (19)
      Tests  189 passed (189)
```

> 教训：`Test Files 5 passed` 这种「全绿」是假的——它只统计**跑起来的**那些。
> 必须同时看 `Errors` 行和退出码。

顺带核实 CI 侧的真实数字（不能只看本机）：

```
$ gh run view 40876718012 --log | grep "Test Files"
web  Test  ...  Test Files  19 passed (19)
web  Test  ...        Tests  189 passed (189)
```

这就是用户直觉里「写了很多但没法用」的来源。

## 做了什么

1. **补 `lib/api.ts` 测试（14 条）**：各端点 URL/方法/载荷、`ApiError` 的 status/message 映射、
   错误体非 JSON 时回退 `statusText`、503 语义、`x-api-key` 有无两态、10s 超时真的 abort。
   结果：0% → **100% 行 / 88.88% 分支**。
2. **补 `app/page.tsx` 冒烟（4 条）**：挂载渲染 / 初始空谱 → 点示例后出现音符列 /
   导出选项「有音符才出现」且可切换 / 播放按钮初态。
   结果：0% → 27.1% 行，顺带把 keyboard 从 0% 带到 24.1%、load-dialog 到 33.3%。
3. **补 Rust `llm.rs` 网络层测试（7 条）**：用 std `TcpListener` 起本地假 OpenAI 端点，
   验证 Bearer 鉴权头、`image_url` data URL、`max_tokens` 预算、`thinking` 撤回重试、
   无关 400 不重试、空 content 报错、500 透出状态与响应体。
   结果：59.80% → **78.05%**。
4. **把假闸门改成真闸门**：
   - Rust：`cargo llvm-cov nextest --lib --fail-under-lines 70`，删掉全部 `continue-on-error`。
   - 前端：阈值写进 `vitest.config.ts`（行 68 / 语句 66 / 分支 58 / 函数 55）。

这是本次最关键的一步。**写完断言必须亲手看它红一次**。

前端：把 `if (!res.ok)` 改成 `if (false)`：

## 踩到的坑

1. **macOS 没有 `timeout` 命令**（exit 127）。要用就在脚本里自己算时间。
2. **覆盖率报告生成吃内存**：本机不加 `NODE_OPTIONS=--max-old-space-size=4096` 会被 SIGTERM（exit 137），
   而测试本身其实已经全过了——报错位置极具误导性。
3. `vitest 4` 的 `--poolOptions.*` 不能当 CLI 参数（`CACError: Unknown option`），只在配置文件里有效。
4. `--reporter=basic` 在 vitest 4 已移除。
5. 主页面测试首次失败是因为 `@/wasm/taiyin_core` 不存在（本地没构建 WASM），
   需要 `vi.mock("@/lib/taiyin-wasm")`——CI 里 WASM 是先构建的，所以两边行为不同。
6. `data-note-column` 一开始断言为 0 是**真实行为**：页面冷启动就是空谱（`useScoreHistory([])`），
   必须先点示例曲谱。测试因此改成「先断言空 → 点示例 → 断言有音符」，顺便把这个行为钉住。
