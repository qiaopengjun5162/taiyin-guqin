## 一、减字谱为什么难数字化

古琴的谱子叫**减字谱**，它不是「音符」，而是**动作指令**——把一句指法说明压缩成一个方块字。

比如「大九勾四」：

| 部件 | 含义 |
|---|---|
| 大 | 左手用大指 |
| 九 | 按在第九徽 |
| 勾 | 右手中指向内拨 |
| 四 | 拨第四弦 |

一个字里塞了四层信息，而且各有各的写法：左手指法用偏旁，徽位用汉字数字，右手指法二十多种还能两两复合（比如「抹挑」），弦序一到七，再叠加散音 / 泛音 / 按音三种音色。写法上还有大有小、有上下叠、有内外嵌——它更像一套**积木拼字规则**，而不是一个现成的字。

![减字字形示例：每个方块字里叠着三到四层信息](fig/jianzi-f2-glyphs.png)

**这就是为什么减字谱在数字世界里几乎没位置**：Unicode 里没有这些字（CJK 汉字区收的是「琴」「瑟」这类普通汉字，不是拼出来的减字），它是历史上手写、后来雕版的一套组合规则。你要么带一套字体把组合规则交给排版引擎，要么自己一笔一笔画。

两头都难：交给字体，就要想清楚几百个部件怎么排布、复合指法怎么嵌套、特殊指法（泛音的「艹」头、打摘之类）怎么降级；自己画，就要接受「每一个减字都是一张小图」，编辑、检索、导出全都要重做一遍。

我选了「字体为主、自己画兜底」的路。这也是后面一切的起点。

## 二、五个月，它长成了什么

从 2026-05-24 第一次提交，到 11 月 6 日拿到公开地址，五个多月，**248 次提交、约 8.6 万行新增**。产品名「太音」，现在能做的三件事、加一个受限的录入入口，全在浏览器里，不需要服务器：

![五个月的提交节奏：按月分布（截至 10-30，累计 130 次）](fig/jianzi-f0-timeline.png)

### 拼：像打字一样拼减字

选指法、点徽位、挑弦序，一个减字就拼出来了。渲染上，约 80% 的字走自带字体的连字排版（部件按压顺序并置，交给 OpenType），剩下 20% 拼不出连字的特殊指法走 SVG 积木降级——四象限画出来，保证**任何组合都能显示**，不会出现「豆腐块」。熟手还有一套连打速记语法，可以像敲五笔一样连续输入一串指法。

### 算：简谱进来，减字出去

输入简谱 `1 2 3 5 6`，选一种定弦——正调、蕤宾调（紧五弦）、慢角调（慢三弦）——工具会给出整段旋律的减字候选。核心是指法编排：同一个音在不同把位、用不同手指都能弹，怎么排才顺手？这里用的是**确定性的动态规划**（Rust 端 Viterbi）：给「换把、过弦、散音连缀」这些动作标好代价，整段一起算全局最优解，再给你多套候选挑。它不是「AI 帮你排」，是一张人手写出来的代价表加一条经典算法——所以同样的输入永远给同样的结果，可以被测试钉死。

### 听：浏览器里直接弹出来

Karplus-Strong 拨弦合成：一根噪声脉冲过一圈带阻尼的延迟线，就是古琴拨弦那股劲儿。散音长、泛音短、走手音带滑，都是模型里调出来的。配节拍器、变速、逐音高亮，导出 WAV 音频、PNG / SVG 图片、PDF 打印稿——离线渲染和实时播放共用同一套合成，所以导出什么音色，听到的就是什么音色。

### 录：干净电子谱面，辅助录入（受限）

上传一张**用本项目字体渲染的干净电子谱面**，工具可以做部件级的辅助录入：单字切分、整页切分、逐格校正，认完反推音高，写入可播曲谱。**标准完整减字（如「大九勾四」）目前认不了**——2026-11-09 的判定是：生产模板库里一条都没有，识别单元和真实减字谱对不上。所以它是辅助，不是一键成谱，结果必须逐格人工核对。

这条线值得多说两句，因为它走了个大弯路。一开始接通用视觉大模型做识别，在 42 个真减字的测试集上 component F1 只有 **23.8%**——更糟的是它给错误答案打 **0.98 的置信度**，任何「低置信度就丢弃」的过滤都形同虚设。后来转念：目标图片大多是字体渲染的电子谱面，根本不需要「看懂」，直接拿项目自带的减字字体渲染成模板图、逐像素比对谁最像就行。**模板匹配一天之内把那 42 个样本从几乎全错拉到全部认对**，加噪、缩放之后依然稳。但这 42 条是字体预烘焙的**复合指法符号**，不是标准完整减字——2026-11-09 复核：生产索引 257 条模板 / 385 条文本里，标准完整减字 0 条，内置曲 27 字 0/27。100% 只证明「同分布自测能查表」。

![识别的两条路径：通用视觉模型 vs 自研字形模板匹配（当时的工程记录；11-09 判定两者都不适用于真实减字谱）](fig/jianzi-f4-two-paths.png)

但边界必须说清楚，而且比当初以为的更窄：这套方法只在**字体渲染的电子谱面**上验证过。真实老谱的异体字、雕版噪声、手写涂改，一个样本都没验过——**而且 2026-11-09 的判定不是「没验过」，是「结构性失效」**：识别单元（部件符号）和真实减字谱对不上。所以我从不说它「拍照就能认老谱」；现在也不能说它「能认减字谱」，只能说它能在干净电子谱面上做辅助录入，结果要逐格核对。

![整页切分：投影找间隙，给每个字画外接框（当时的工程记录，不代表当前能力）](fig/jianzi-f5-segment.png)

## 三、外观：把国风和科技感焊在一起

之前界面偏朴素，被吐槽「没有和中国传统文化结合、没有未来感」。于是重做了一套：

- **背景**：墨色底 + 七弦纹（国风根基）+ 极淡的青碧科技网格 + 缓慢流动的辉光晕（科技感）；
- **卡片**：宣纸底 + 青碧 → 金 → 朱砂渐变描边 + 四角 HUD 直角标 + 柔光；
- **品牌头**：朱砂印章 + 书法标题 + 一个带脉冲呼吸的 AI 徽标；
- **首页压短**：原本竖着的大印章压成一行顶栏，四行散落的控件合并进一张「演奏控制台」卡片，桌面端自动双列 → 高度大约砍掉一半。

![重做后的完整界面：墨色底、宣纸卡片、青碧金朱砂描边](fig/jianzi-f3-app-full.png)

改完用户说「这才对」。国风不是贴一张祥云壁纸，是让「减字、徽位、朱印」这些本有的元素站到视觉第一排；科技感也不是加霓虹灯，是网格、直角标、脉冲这些「仪器感」的克制点缀。两边焊在一起，才不土。

## 四、上线：免费托管，纯前端

核心功能全在浏览器跑（Rust 编译的 WASM + 257 条复合指法 / 部件模板索引，注意不含标准完整减字），**不需要后端服务器**。社区、账号、云同步那条线需要服务端，暂时没接——但正好让上线变得简单：GitHub Pages 和 Vercel 都是纯静态托管，从 `main` 分支一推就自动部署，一分钱不花。曲谱存浏览器本地，PWA 注册过之后还能离线用。

踩的坑值得记一笔：Vercel 单项目导入只拉 `apps/web`，仓库根的 WASM 源码不在构建环境，WASM 二进制又被 `.gitignore` 排除。结果是构建脚本找不到文件、直接退出码 127。根因修复有两个动作：**强制提交预编译的 wasm 到仓库**，以及把 Vercel 的构建命令从「跑整套脚本」改成「纯前端 `pnpm build`」。之后一次构建 30 秒出头就 Ready。

两个地址互为镜像，挂了一个还有另一个——对纯前端项目来说，这是零成本的冗余。

## 五、现在能玩什么

打开任一地址，刷新即用。几条最短路径：

**只想听**：首页点开示例曲谱（《花非花》《沧海一声笑》《仙翁操》《泛音练习》四首），空格键播放，看减字随旋律逐个亮起，变速、节拍器随手切，喜欢就导出 WAV 或 PDF。

**想自己拼**：在拼字面板点指法、徽位、弦序，一个减字就落进曲谱；撤销重做、单字另存 PNG / SVG 都有。熟手可以试连打速记，一串键入一个乐句。

**手头只有简谱**：粘贴 `1 2 3 5 6` 这样的简谱，选定弦，工具给出多套减字候选（散音 / 按音 / 泛音各有编排），挑一套确认入谱，然后逐句慢练——练到哪句、练了几遍，进度留着，下次接着来。

**手里有电子谱面**：上传一份用本项目字体渲染的干净谱面，可做辅助录入——切分 → 逐格校正 → 反推音高 → 写入曲谱。标准完整减字目前认不了，必须逐格人工核对；别指望一键成谱。

## 小结

五个月，**248 次提交、约 8.6 万行新增**，代码 90% 由 AI 写，人只做判断（目标、eval、架构、红灯真伪）。背后是一堆自动化闸门：**153 个 Rust 测试、80 个前端测试文件共 1200 余条用例、行覆盖率闸门 92%、6 个 CI workflow** 盯着每一次 push。

如果想做自己的 side project，我的三条经验：

1. **把工程当研究做**：先怀疑 eval、再怀疑环境、最后才怀疑模型——顺序反了，坑一个都看不见。识别那条线如果早测两天，能少写一周废代码。
2. **静默失败是最大敌人**：不对但不报错，比功能不对更糟。要么正确，要么大声报错——「拼不出的减字就走 SVG 画出来」就是这个原则的产物。
3. **先有闸门，才敢少看**：不是先少看再补测试，而是先有测试，才敢把实现交给 AI。153 + 1200 这个数字不是拿来吹的，是「敢放手」的前提。

真实的坑，比漂亮的架构图有人看。
