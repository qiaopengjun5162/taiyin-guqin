# 写作素材库（article material archive）

这个目录**不是产品文档**，是写文章的原材料仓库。

理由很直接：这个项目从 2026-05-24 到 2026-10-29 做了 5 个月、118 次提交、2 万多行改动，
里面有大量**真实的判断、真实的报错、真实的数字**。这些材料如果不当场记下来，过两周就只剩
「好像当时有个坑」这种没法写进文章的记忆。而读者真正愿意读的，恰恰是那些具体的坑。

## 三层结构

| 目录 | 放什么 | 写作阶段的角色 |
|---|---|---|
| `material/` | 一次操作一条记录：意图、输入、命令与真实输出、卡点、解决、结论 | **原材料**（唯一事实来源） |
| `drafts/` | 面向读者的长文草稿，按 `NN-标题.md` 编号 | 成品 |
| `assets/` | 截图、生成的图、图表（`YYYY-MM-DD-用途.png`） | 插图 |

`timeline.md` 由 `scripts/gen-article-timeline.sh` 从 git 日志生成，是所有文章的骨架。

## 素材条目：一次操作一条

模板见 `_template-material.md`，六个必填段落：

1. **意图** —— 当时想解决什么问题（一句话，别写背景）
2. **输入** —— 手里有什么：报错、需求、别人给的 key、现有代码位置
3. **操作与真实输出** —— 命令 + **原样粘贴的输出**（成功也算，失败更要）
4. **卡点与解决** —— 现象 → 定位过程 → 根因 → 改法。这里最容易写出价值
5. **结论与可引用点** —— 这次拿到了什么数字/结论，哪句可以直接进文章
6. **资产** —— 截图路径、commit hash、相关文件

## 六条纪律

1. **做完就记**，不要攒。攒下来的记录一定是回忆，回忆一定失真。
2. **输出原样贴**，包括报错全文、耗时、文件大小。不要「大概用了 1.5 秒」，写 `1.4s`。
3. **密钥一律打码**：`sk-c07…fb98`。真 key 只进环境变量，不进仓库。
4. **失败比成功值钱**：踩过的坑要写「我以为是什么 → 实际是什么」，这是文章的高光段落。
5. **必留 commit hash**，让读者（和未来的自己）能对到代码。
6. **截图存 `assets/`** 并压到 500KB 以内（`magick -resize 1280x -strip -quality 82`）。

## 从素材到文章的三步

```bash
# 1) 生成/刷新时间线骨架
bash scripts/gen-article-timeline.sh

# 2) 从 material/ 里挑 5–8 条「有冲突感」的条目（有坑、有反转、有数字）

# 3) 在 drafts/ 里按「问题 → 选择 → 踩坑 → 数字 → 方法」串起来，别按时间流水账
```
