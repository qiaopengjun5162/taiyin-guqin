# 太音古琴 · 入口形态规划（小程序 / PWA / APP）

> 目的：回答"未来要不要做 APP / 小程序、怎么做、先做哪步"。
> 给非技术背景看结论，给执行同事看落地方案。
>
> **结论先行**：太音目前**只有网页版**，没有 APP、也没有小程序。建议分两步走——**先用 PWA 给网页"加壳救急"，再上微信小程序做 MVP**；原生 APP 暂不做。好消息是：减字识别已是纯前端（WASM）算法，小程序 MVP 不必先上云，成本比想象中低。

---

## 一、现状：现在用户怎么用太音

- **形态**：网页应用。古琴核心逻辑（减字识别等）编译成 WASM 跑在浏览器里；曲谱库存 Postgres。
- **部署**：GitHub Pages，访问路径 `https://<用户名>.github.io/taiyin-guqin`。
- **能做什么**：减字谱识别（拍照/传图→识别）、实时拼减字、播放、曲谱管理。
- **痛点**（用户原话"上手太难、没人用"拆开看）：
  1. **找不到**——GitHub Pages 长链接，无独立域名、无应用商店、无搜索曝光，只能靠文章里丢链接。
  2. **不会用**——首屏就是"选音色→点指法→点弦徽→拼减字"，对路人偏重。
  3. **没"装上"的感觉**——手机浏览器关了就没了，无留存。

## 二、竞品参照（用户分享的文章）

- **忘机减字谱**（2026-09 第一轮内测）：**最值得重视的竞品**——它也是"减字谱编辑器"，做了一年多，自研排版渲染引擎。能力覆盖：减字谱拼音输入法、简谱自动生成（含同声/应合/放合/分开等联袂指法）、时值拖拽修改、三种布局（自然流式/小节换行/等宽小节）、试听校对、PDF/图片导出。定位是**专业打谱工具**，面向"会整理录入琴谱的人"，桌面端内测。
- **如意谱斋**（国琴网介绍）：真实古琴打谱软件，macOS + Windows **桌面端**，能简谱转减字谱、试听、导出 PDF。做的也是"打谱"。
- **玉晴如是古琴**：线装乐律教材 + 范煜梅"中乐调音软件"，仍是传统/桌面路线。
- **丝桐 / 丝桐里（丝桐科技）**：古琴移动 APP 家族。**「丝桐」练习 app**（2018 上线，iOS 优先）主打练习陪伴——曲库、A/B 句练习、录音回放、延音工具、减字谱展示；**「丝桐里」**补上减字谱输入法（弦序+徽位组合键）、调音器、节拍器、音位图、乐谱分享。覆盖"练习 + 输入"，但**仍要用户已有谱或手动输入，无识别**。
- **火蜘蛛 × 太一散人 古琴减字谱输入法**（2025-01 上线）：**键盘输入法**（敲击键盘生成减字符号），界面简洁、多字体支持，定位学习/教学/创作记谱。纯**输入向**工具，非 APP、非识别。
- **启示（关键）**：
  - 古琴"减字谱编辑器"赛道**已有人认、有需求**（忘机验证了这点），但现有玩家**全是专业打谱向（重做谱、桌面端）**。
  - **太音绝不能去和它卷"做谱深度"**——忘机已投入一年多的排版引擎，正面竞争必败且无意义。
  - **整个"减字"生态都是"输入向 / 练习向"，且都要求用户已有谱或手动产生减字**：丝桐/丝桐里（练习+组合键输入）、火蜘蛛（键盘输入法）、忘机（拼音输入法）——连"练习 app"都只展示已有减字谱、不识别。**没有任何一款做"识别向"（拍照/传图→自动认减字）**。这正是太音的差异化窗口：**别人比"怎么方便输入/怎么陪练"，太音做"怎么免输入直接认"**；用户"上手难"的根源正是"要会输入/会读谱"，拍照识别恰好绕开它。
  - **空白在"轻"**：微信里的小程序、普通琴友"随手拍就听"的体验，目前**没有任何竞品占住**。这正是太音的差异化窗口：**忘机是"我手写谱"，太音该是"我拍一下就听"**。
  - 小程序 MVP 必须把"拍照识别减字谱→直接听"这一屏做到**极致简单**，这是对抗忘机重体验的唯一正确打法。

## 三、三条路对比（大白话）

### 路线 A：微信小程序 —— 最高优先级（对抗忘机的核心抓手）

- **是什么**：微信里点的"轻应用"，不用下载，点开即用，能转发给琴友、能被搜到、能扫码进。
- **为什么最适合你**：你的用户全在微信（文章在微信发、琴友在微信聊），小程序是"顺手"的入口。
- **怎么实现**：
  - 前端框架：**Taro 4.x（React 写法编译成微信小程序）**——可直接复用太音现有的 React 组件逻辑，省约一半工。具体配方见下方「具体技术配方（参考 roselet 项目）」。
  - 识别：太音的减字识别是确定性模板匹配，已编译成 WASM（taiyin-core），**小程序支持 WASM，可纯前端跑**——MVP 不必先上云后端。
  - 首屏极简设计（关键·对标忘机）：打开小程序 → 拍照/传一张减字谱 → 自动识别 → 直接播放/查看。这一屏就把"上手难"打掉，也正好和忘机"重做谱"形成错位——**它越专业，我们越要轻。**
- **工作量（粗估）**：纯前端 MVP 约 **2–4 周**（含移动端交互打磨）；若要曲谱库/保存，再加云后端 1–2 周。
- **成本**：微信认证（企业 300 元/年；个人主体类目受限，建议用企业/组织主体）。
- **坑**：微信内容审核（古琴内容一般没问题，AI/识别功能要写清用途）；WASM 在小程序里需按基础库要求分包加载。

### 路线 B：PWA（网页升级版）—— 推荐现在先做

- **是什么**：给现有网页加一个"安装清单"，手机浏览器里能"添加到主屏幕"，图标像 APP，离线也能开一部分。
- **为什么先做它**：改动最小（现有 Next.js 加壳即可），几天到一周，立刻解决"没装上/找不到"的燃眉。
- **怎么实现**：加 `manifest.json` + service worker（现成库 next-pwa），顺手把移动端交互再打磨一轮。
- **局限**：iOS 的 Safari 对 PWA 支持弱（加到桌面后体验打折）；应用商店里搜不到。
- **工作量**：几天 ~ 1 周。

### 路线 C：原生 APP（iOS / 安卓）

- **是什么**：应用商店下载的真 APP。
- **为什么暂不做**：要写两套（iOS + 安卓）、过商店审核、长期维护，成本最高、见效最慢。等小程序验证"真有这批用户"后再说。
- **何时考虑**：小程序跑出稳定日活、用户主动要 APP 时。

## 四、推荐路线图

| 阶段 | 做什么 | 目标 | 周期 | 成本 |
|---|---|---|---|---|
| **阶段 0（现在）** | 网页 PWA 化 + 手机适配 + 公众号文章引流 | 解决"找不到/没装上" | ~1 周 | 极低 |
| **阶段 1（核心·最高优先级）** | 微信小程序 MVP：首屏=拍照识别减字谱→直接听（纯前端 WASM） | **对标忘机、占住"轻体验"空白** | 2–4 周 | 低（认证费为主） |
| **阶段 2** | 小程序完善：拼字编辑、曲谱库（上云）、分享、歌词；并补**实用工具**（曲库/调音器/节拍器/音位图——丝桐里已验证这些是琴友日常刚需） | 留存与口碑 | 持续 | 中（云资源） |
| **阶段 3（可选）** | 原生 APP / 桌面端 | 扩平台 | 视需求 | 高 |

> 阶段 1 之所以能压到 2–4 周，是因为识别核心已是 WASM、可纯前端跑；只有到了"保存曲谱/多人协作"才必须上云后端。

## 五、后端上云（做曲谱库时绕不开，MVP 可暂缓）

- **现状**：Postgres 只存 `scores` 表（标题/音符/时间），即**曲谱库**；识别本身是 WASM 前端算法。
- **小程序限制**：前端不能直连数据库、不能藏 API key。
- **但 MVP 可不做保存** → 先"识别→播放"，纯前端跑通，**暂不上云**。
- **何时上云**（阶段 2）：要曲谱库/跨设备/多人时，选一种：
  - 微信云开发（和微信生态最贴，起步快）
  - 腾讯云 / 阿里云 容器 + 云数据库
  - Supabase（开源，带鉴权+数据库+存储，开发快）
- **注意**：若引入 AI 辅助选候选（llm.rs 用的便宜模型），其 API key 必须放服务端，绝不下发前端；且模板匹配本身已 100% 准确，MVP 可先只用模板匹配、跳过 AI。

## 六、一句话定位（和竞品区分）

- **忘机减字谱** = "我认真做谱"（专业打谱工具，桌面端内测，做谱深度强）
- **如意谱斋** = "我手写谱"（打谱工具，桌面端）
- **丝桐里** = "我手机输入谱"（已上线古琴移动 APP，输入向，含曲库/调音/节拍器/音位图等实用工具）
- **火蜘蛛输入法** = "我敲键盘出谱"（古琴减字谱键盘输入法，输入向）
- **太音小程序** = "我拍一下就听"（识别 + 拼字 + 播放，首屏极简，**零输入**），给不会打谱、不会输入的普通琴友用
- **策略**：不与忘机/如意谱斋卷做谱深度，也不和丝桐里/火蜘蛛卷"输入便利"；固守"识别向、零输入、上手零门槛"的独有差异化。

## 七、风险与回滚

- **小程序审核被拒**：内容类目选"工具/教育"，提前备好功能说明；被拒可改类目重提。
- **WASM 在小程序加载问题**：用分包 + 基础库要求处理，MVP 先验证最小识别链路。
- **云费用失控**（阶段 2 起）：先用按量计费 + 限额告警，MVP 期几乎零费用。
- **多端维护人力**：阶段 0/1 只维护"网页 + 小程序"两端，APP 不碰，控制人力。

---

## 八、下一步建议

1. **立刻（阶段 0）**：把网页 PWA 化，配合你正在发的公众号文章引流——用户点文章链接就能用、能加到桌面。
2. **最高优先级（阶段 1）**：让同事按现有 React/WASM 逻辑评估 Taro 小程序化工作量，准备 MVP 立项；先验证"拍照识别→直接听"最小闭环。这是对抗忘机、占住轻体验空白的关键，**建议与阶段 0 的 PWA 并行推进，但小程序立项不拖。**
3. **决策点**：小程序 MVP 上线后看留存，再决定是否做曲谱库（上云）与 APP。
