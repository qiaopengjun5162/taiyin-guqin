# 免费部署指南（静态前端）

太音古琴前端是 `next build` 的**纯静态导出**（`next.config.ts` 里 `output: "export"`），
产物在 `apps/web/dist`，不含任何服务端逻辑。**减字识别（模板匹配）、播放、WAV/PNG/SVG 导出、
本地曲谱全部在浏览器运行**，因此不依赖我们自己的后端即可完整使用。

> 后端（社区 / 账号 / 云同步）是另一条线：等你能连上服务器、或买个便宜 VPS，用
> `scripts/deploy-to-server.sh` 一把上。下面三个方案**只覆盖前端**。

## 三个免费托管平台对比

| 平台 | 费用 | 默认域名 | 后端 | 构建机自带 Rust？ |
|---|---|---|---|---|
| GitHub Pages | 免费 | `*.github.io/taiyin-guqin` | ❌ | 用我们自己的 CI（已装）|
| Vercel (Hobby) | 免费 | `*.vercel.app` | ❌ | ❌ 脚本自动装 |
| Netlify (Free) | 免费 | `*.netlify.app` | ❌ | ❌ 脚本自动装 |

## 环境变量（三个平台通用）

| 变量 | 值 | 含义 |
|---|---|---|
| `BASE_PATH` | `""`（Vercel/Netlify）或 `/taiyin-guqin`（GitHub Pages）| 站点挂载路径；根路径部署留空，GitHub 子路径项目页写子路径 |
| `NEXT_PUBLIC_API_URL` | **留空** | 空 → 纯前端模式（browser-only），识别/导出全在浏览器；填上后端地址 → 连后端（需后端在跑）|

> 当前线上默认就是 browser-only（仓库变量 `TAIYIN_API_URL` 已删）。想要连后端，在对应平台
> 的 Environment Variables 设 `NEXT_PUBLIC_API_URL=https://你的后端域名` 并重部署即可。

## 零配置已就绪的文件

仓库里这些文件已经写好，平台会自动读取，基本不用手填：

- `scripts/build-static.sh` —— 一键构建（装 Rust+wasm-pack → 编 WASM → 导出静态站）
- `vercel.json`（仓库根，供「根目录项目」用）与 `apps/web/vercel.json`（**Vercel 单项目导入 `apps/web` 时自动读取，推荐路径**）—— 构建命令 / 发布目录 / `BASE_PATH` / `PNPM_VERSION` / SPA 兜底，两份内容对应各自项目根。
- `netlify.toml` —— Netlify 自动读取（同上）
- `.github/workflows/pages.yml` —— GitHub Pages 自动读取

## A. GitHub Pages（已上线，零操作）

仓库 push 到 `main` 即自动构建并发布到
`https://qiaopengjun5162.github.io/taiyin-guqin`。首次部署已完成，**现在就能用**。

切到「连后端」模式：仓库 Settings → Secrets and variables → Actions → Variables →
新建 `TAIYIN_API_URL=https://你的后端域名`，重跑 Pages 工作流（或随便再 push 一次）。

## B. Vercel

1. 打开 https://vercel.com ，用 GitHub 登录。
2. 点 **Add New… → Project**，授权后仓库列表里选 `taiyin-guqin` → 进入导入页。
3. ⚠️ **这个仓库是 monorepo，Vercel 会检测出 3 个应用（`apps/web` 前端、`crates/taiyin-server`
   后端、根目录容器）。我们只部署前端——不要选根目录的 Services（那会试图部署后端/容器，复杂且
   我们不需要）。请点 `apps/web` 这一行右侧的「Import single project →」。**
4. 项目根会变成 `apps/web`，`apps/web/vercel.json` 自动被读取，配置基本免填。核对一下：
   - Framework Preset：**Other**（由 vercel.json 的 `framework: null` 控制）
   - Root Directory：`apps/web`
   - Build Command：`bash scripts/build-static.sh`（脚本会自动回到仓库根编译 WASM）
   - Output Directory：`dist`
   - Environment Variables：`BASE_PATH` = **（空串）**、`PNPM_VERSION` = `11`（都已自动设）
5. 点 **Deploy**。首次构建会装 Rust + wasm-pack（约 3–5 分钟），之后有缓存更快。
6. 得到 `https://<项目名>.vercel.app`（具体域名由项目名决定），直接打开即用。

> 若构建报 pnpm 相关错误：确认 `PNPM_VERSION=11` 已注入（vercel.json 已设）；仍异常时到项目
> Settings → Build & Development 里手动把 Package Manager 设为 pnpm 11。

## C. Netlify

1. 打开 https://app.netlify.com ，**Add new site → Import an existing project**，
   选 GitHub，授权后选 `taiyin-guqin`。
2. `netlify.toml` 已写好，构建命令 / 发布目录 / 环境变量会自动读取。若手动填：
   - Build command：`bash scripts/build-static.sh`
   - Publish directory：`apps/web/dist`
   - 环境变量：`BASE_PATH` = **（空串）**，`NODE_VERSION` = `22`，`PNPM_VERSION` = `11`
3. 点 **Deploy site**。完成后在 **Site settings → Domain** 可改子域名或绑自定义域名。

## 常见问题

- **首次构建慢**：脚本要在构建机上装 Rust 工具链 + wasm-pack（一次性）。GitHub Pages 走我们自己
  的 CI（已缓存），反而最快。
- **深链接刷新 404**：已加 SPA 兜底（Vercel `rewrites` / Netlify `[[redirects]]` 指向
  `index.html`），正常不会出现。
- **识别 / 导出用不了**：确认 `NEXT_PUBLIC_API_URL` 是空（browser-only）。若填了后端地址但后端
  没跑，会 503。
- **改了代码怎么更新**：三个平台都是「push 到 main 自动重新部署」，无需手动操作。

## 后端那条线（可选，进阶）

前置三件事（需机器主人动手，或在一台能免密 SSH 到服务器的机器上操作）：

1. 服务器 SSH 公钥配好
2. DNS A 记录指向服务器 IP
3. 后端 SMTP 授权码（社区邮件用）

备好后在能连服务器的机器跑：

```bash
bash scripts/deploy-to-server.sh ubuntu@服务器 taiyin.qintopia.cn
```

一键：预检 → 起库起后端 → 接 nginx/caddy 签 HTTPS → 线上验收 → 设 `TAIYIN_API_URL` 让全站连后端。
