## 为什么这里放的是原样文件

2026-11 之前本站分发的是**改过的副本**：名称表里 `Copyright` 被替换成
`Modified for Taiyin Guqin Project`，厂商 URL（nameID 11）被抹掉，文件名也改成了
`TaiYinJianZiPuKaiTi.ttf`。

这么做有两处问题：

1. **违反 OFL**。许可要求分发时保留版权声明与许可文本；改动后两样都没了，
   等于把别人的署名换成了自己的。OFL 允许修改，但必须保留原作者版权，
   且衍生版不得使用其保留字体名。
2. **没有必要**。逐字形比对确认：那份副本与官方原件**只有 1 个字形不同**
   （`placeholder` 占位字形），全部 advance 相同，渲染像素级一致。
   换句话说，改动没有带来任何功能收益，只带来了署名风险和一份维护负担。

现在分发官方原件，本站只做一件事：在 CSS 里用 `font-family: "WangJiJianZiPuKaiTi"`
引用它。CSS 别名不是对字体文件的修改。

## 怎么用

字体靠 **OpenType 情境替换（`calt`）** 组字：按传统书写顺序输入指法文字
（如 `大九绰勾四`），浏览器排版时自动把这串字叠成一个方块谱字。

几条来自官方规格、必须遵守的规则：

- **每个谱字后必须跟一个空格**，空格是组字的结束锚点。缺空格时相邻谱字会粘连错位。
  本站逐字渲染，天然一次只排一个谱字，所以代码里不追加空格；但**泛音**是例外——
  `泛` 必须用空格与后续指法隔断，否则会被 GSUB 链吞进同一个字（见 `lib/jianzi.ts`）。
- **分数要紧跟徽位**：`大九六绰勾四` 成字，`大九绰六勾四` 散成两串。
  序列化顺序即由此确定，不是排版偏好。
- **`十二` 会被读成「十徽二分」**，`十二徽` 才是十二徽。两字徽位（十一/十二/十三）
  再接分数时字体无法消歧，本站对这类组合降级为 SVG 积木渲染
  （判据见 `components/jianzi-block.tsx::needsSvg`，附实测依据）。

## 改过的那份副本里，有一处真问题——但不是靠改名解决的

旧副本做了一件事：把 `placeholder` 字形清空。这个字形是**必须知道的坑**：

- 它有 134 条轮廓、bbox `3772 × 1538`（近 3.8em 宽），是一块巨大的填充图形；
- 官方字体把它映射到 **75,679 个码位**（ASCII、`、`、`，` 等标点几乎全部在内，
  总共 76,148 个映射里只有 469 个指向真字形）；
- 也就是说：**任何没被字体收录的字符，都不会显示成空白或豆腐块，而是这个巨幅图形。**

本站目前不会踩到，因为只有 `JianziBlock` 用这款字体，而它只渲染
`jianziToText()` 产出的字符——全部落在真字形上（散/泛、名/食、勾/抹/挑/托/劈/打/摘、
徽位与分数汉字、弦序汉字、绰/注/急）。键盘上的偏旁按钮（夕/亻/乇/勹/木/尸/丁/倽）
**落在这个 placeholder 上**，所以键盘一律用系统字体，绝不能套这款字体渲染。

要做新的界面时请守住这条：**别把这款字体用作通用 `font-family`**，
只用来排已经确认能组字的指法串。

## 改动本目录时

- 升级字体：从官网下载，核对 md5 后替换，跑 `apps/web/e2e/smoke.mjs` 确认
  `document.fonts.check` 通过、减字没有退化成汉字。
- **不要**再改字体的名称表或轮廓。要加自研字形，请另做一份字体并单独声明许可，
  不要混进这个文件（OFL 禁止把不同许可的字体合并进同一文件）。
